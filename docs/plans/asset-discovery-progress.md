# Bounded asset discovery

The deployed asset search walks the complete subtree before selecting a page.
A preserved live run refused the broad root after exhausting its existing
budget. The correction must return bounded progress and continue from retained
provider iterators, using the existing runtime cursor owner. It must preserve
the full search question, every filtering criterion, caller authority, resource
cleanup, all numeric limits and the complete original project gates.

The asset result moves to semantic major version two because provider traversal
order and explicit `complete` and `examined_nodes` fields differ from the old
globally sorted result. The original argument shape remains unchanged. The
shared canonical array rule changes only for asset matches; all other array
rules remain unchanged. Other commands receive the patch increments required
by changed shared metadata. Every generated schema role and identity field must
be reviewed against the preserved original snapshot.

Producer metadata must satisfy the existing consumer contract: size comes from
the original binary, media format uses one usable metadata string and then the
original rendition's MIME type, a size filter excludes unknown size, omitted
tag mode requires all requested tags, and returned tags are unique in UTF-8 byte
order. Synthetic independent regressions precede each correction. Reading size
must not download the binary. Root-only searches include assets with absent
optional metadata; requested missing metadata never becomes a match.

The implementation footprint is:

- Java asset command, handler, result materialization and regression tests;
  the existing runtime registration and affected paging-admission fixtures.
- Native asset result types and tests, shared incremental validation, schema
  generation and command classification; affected structured-result tests.
- Generated command schemas in both repositories, shared canonical/contract
  digests, all command identity metadata and affected existing wire fixtures.
  Preserve fixture inventories and add explicit new progress, replay, ordering,
  metadata and boundary cases. Do not conceal failures by refreshing a policy
  baseline or raising a bound.
- Accurate command documentation, the original public pair harness and an
  independently planted large-tree asset scenario with exact count witnesses.
- External private-free observers, immutable source/diff/gate/candidate receipts,
  deployment-input checks and current-generation coverage binding.

The release requires all original complete gates, the entire public integration
matrix with the exact acknowledged artifacts, selected archive privacy,
authorized deployment, fresh compatibility and live discovery/lifecycle checks,
complete owned cleanup and final local idle evidence. The earlier asset budget
refusal remains a failed historical observation. No live response, configured
destination, customer name, credential or runtime identity fingerprint may be
written to evidence. All builds, gates, preparation and probes use the existing
resource guard, with one heavy workload at a time and the agreed half-machine
ceiling. This correction does not complete the broader effectiveness objective.
