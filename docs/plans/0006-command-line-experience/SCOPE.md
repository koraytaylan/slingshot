# Plan 0006 — Command-Line Experience

> Make every Slingshot operation scriptable from one predictable command surface that reaches exactly one namespaced daemon and keeps progress, results, and failures mechanically separable.

## Why this plan

The command line is both the direct operator interface and the executable seam used by shell automation. It must cover the entire operation registry without inventing a second request model, select the same `(profile, environment)` namespace every time, start that namespace's daemon when required, and let a long-running Sling Job outlive the terminal that submitted it. Output behavior is part of this contract: a person needs concise progress and artifact locations, while automation needs one versioned JSON value whose fields and exit classification do not depend on terminal detection.

## In scope

- **0025 — Invocation and Daemon Selection.** Register the complete compiling Plan 0006 module inventory once, define leaf-scoped selection, rendering, detachment, and operation-key options, implement a local-only configuration check, expose explicit daemon start/status/ping/stop lifecycle, authenticate exact `slingshot.daemon-runtime-contract/1` digest on every versioned local request while retained control remains usable under mismatch, reject stale target identity, and connect to or start exactly one daemon for the selected profile and environment.
- **0026 — Command Catalog.** Bind every operation to the registry's exact `1.0.0`, canonical command-limits digest, annotated role schemas, typed arguments, and failure inventory; authenticate the exact `slingshot.command-canonical-json/1` artifact/digest through the schema manifest and both `x-slingshot-canonical-json-contract-sha256` annotations without changing the five-field durable identity; validate raw role bytes before Draft 2020-12 shape and typed construction; preserve SearchPhrase bytes, construct canonical asset request sets, keep bounded continuation tokens opaque, and generate help without a parallel contract.
- **0027 — Operation Observation.** Support attached/detached submission and durable observation/maintenance/artifact workflows; require exact `slingshot.author-agent-transport-contract/1` digest on current agent-backed provenance; preserve complete over-inline maintenance values through Plan-0004-owned operation-free target-qualified associations with identical CLI/Model Context Protocol identity, metadata-then-read authentication, bytes, and digest; make non-overwriting atomic operation-artifact or maintenance-result publication the success commit and retain an exact receipt until success output commits; render the shared machine outcome envelope with conditional recovery/terminal evidence and every revised closed semantic failure object without aliases or lost fields; classify exits from authoritative disposition rather than failure-name heuristics; and give pre-receipt admission-unknown, post-receipt observation-detach, pre-publication artifact-transfer, and pre-publication maintenance-result-transfer interruption distinct truthful human/JSON outcomes without remote cancellation.
- **0028 — Process Contract Proof.** Exercise the compiled executable with canonical-contract and exact catalog-identity drift refusal, raw-byte/schema/typed ordering, absent/reused/concurrent daemon startup, publication-versus-rendering signal races, early-exit/readiness failure, post-admission lost-receipt replay, every revised configuration/FileVault/add-component/continuation failure in human and machine modes, nonce-bound cooperative cleanup plus retained instance-handle fallback without process-identifier signaling races, secret scans, and generated reference coverage.

## Out of scope

Direct Adobe Experience Manager network calls from the command-line process, interactive full-screen interfaces, shell command evaluation, implicit publisher selection, cancellation of a Sling Job on terminal interrupt, and operation definitions that are absent from the shared registry are excluded. The daemon, agent transport, operation registry, and durable operation state are supplied by earlier plans; this plan is their local client.

## Command surface

Every ordinary daemon-backed invocation accepts `--profile <name>` and `--environment <name>`, or resolves the explicit defaults defined by Plan 0002. Applicable ordinary leaves accept `--output human|json` for final rendering, and submission leaves alone accept detachment and operation-key options. Plan 0007's standard-stream server leaf accepts only profile/environment selection and rejects ordinary rendering, detachment, and operation-key options. The stable command groups are:

```text
slingshot content load <path> --representation json [--depth <count>]
slingshot content replicate <path> [--recursive]
slingshot package download --name <name> --root <path> [--root <path>]... [--include <pattern>]... [--exclude <pattern>]...
slingshot configuration inspect <persistent-identifier>
slingshot query paths --root <path> [--node-type <type>] [--property-predicate <canonical-json-object>]... [[--offset <count>] [--limit <count>] | --continuation-token <token>]
slingshot query pages --root <path> --contains <phrase> [[--offset <count>] [--limit <count>] | --continuation-token <token>]
slingshot query pages --root <path> --template <path> [[--offset <count>] [--limit <count>] | --continuation-token <token>]
slingshot query pages --root <path> --uses-component <resource-type> [--uses-component <resource-type>]... [--match any|all] [[--offset <count>] [--limit <count>] | --continuation-token <token>]
slingshot query assets --root <path> [--format <media-type>]... [--minimum-bytes <count>] [--maximum-bytes <count>] [--tag <tag>]... [--tag-match any|all] [--property-predicate <canonical-json-object>]... [[--offset <count>] [--limit <count>] | --continuation-token <token>]
slingshot query assets-used-by-page <page-path> [[--offset <count>] [--limit <count>] | --continuation-token <token>]
slingshot page create --parent <path> --name <name> --title <title> --template <path> [--properties-file <path>]
slingshot component add --page <path> --parent-resource <relative-path> --name <name> --resource-type <resource-type> [--properties-file <path>]
slingshot configuration check
slingshot daemon start|status|ping|stop
slingshot operation list [--author-target-identity-digest <digest>] [--state <state>] [--limit <count>] [--continuation-token <token>]
slingshot operation status|result <operation-identifier> [--author-target-identity-digest <digest>]
slingshot operation wait <operation-identifier>
slingshot operation resume <operation-identifier> --expected-revision <revision> --expected-recovery-category <category>
slingshot operation artifact <operation-identifier> <artifact-identifier> --destination <path> [--author-target-identity-digest <digest>]
slingshot maintenance preview --before <date-time> --limit <count> [--author-target-identity-digest <digest>]
slingshot maintenance apply --preview-digest <digest> [--author-target-identity-digest <digest>]
slingshot maintenance result <maintenance-result-identifier> --expected-digest <digest> --destination <path> [--author-target-identity-digest <digest>]
```

Any submission command also accepts `--detach` and `--operation-key <key>`. The key is required for every registry operation not classified intrinsically idempotent: content loading (whose bounded result may publish a retained remote artifact), replication, content-package download, page creation, and component addition. Thus the current catalog has seven intrinsically idempotent commands and five caller-key-required commands; read/write classification alone never decides the requirement. A client lost after admission can be rerun explicitly against the same operation. The seven intrinsically idempotent configuration/discovery operations may omit the key; the command-line process then creates one identifier before its first request and retains it for in-process reconnects. Those options and `--output` are leaf-scoped rather than parser-global and are rejected on `model-context-protocol serve`. Every discovery command accepts `--offset` and `--limit`, or the mutually exclusive `--continuation-token`. Each `--property-predicate` value is one canonical JSON object from the shared typed predicate schema; operator-specific fields and arity are validated before daemon access.

Help and version are the only metadata-only commands. `configuration check` resolves the selected profile and environment and safely validates referenced credential, additional certificate authority, Cloud credential JSON, private-key, and target-revision inputs without starting or connecting to a daemon and without making a network request. Daemon `status`, `ping`, and `stop` probe only an existing name-derived namespace and never start one; `start` explicitly starts or joins it. Every daemon execution request and readiness handshake carries the current `AuthorTargetIdentity` and `SelectedEnvironmentRevision`; an old daemon with a different value is refused with explicit stop/start guidance. Observation and maintenance default to the current author-target partition. List, status, operation result/artifact, and maintenance preview/apply/result may name a historical `AuthorTargetIdentityDigest`; historical observation is terminal and read-only. Maintenance preview returns the complete bounded canonical effect/capacity manifest and its digest for one partition, while apply requires that digest and the same selected partition, accepts no age/limit criteria that could silently select a different set, and durably replays an exact previously applied digest. An over-inline preview or applied/replayed result returns the exact operation-free target-qualified URI `slingshot://profiles/{profile}/environments/{environment}/targets/{author_target_identity_digest}/maintenance/results/{maintenance_result_identifier}`; `maintenance result` obtains current association facts through target-and-identifier-only `MaintenanceResultMetadata`, requires its caller-supplied expected content digest to match, then fetches through `MaintenanceResultRead` and revalidates the full read-start metadata under the unchanged-or-sole-apply-transfer rule before atomic publication. It never inverts the identifier hash. Preview replay/restart preserves the URI; preview supersession and completed-receipt retirement before read start make the former association unreadable. Wait, recovery resume, submission, and mutation reject historical digests. Recovery resume requires the caller's observed operation revision and exact observed recovery category and acts only on a fresh current-target manually resumable `RecoveryRequired` state. Every such state displays either execution certainty or fieldless authoritative remote success; post-success capacity/result/artifact acquisition never invents certainty. Repeating exact committed source preconditions returns the durable resume receipt and truthful current status without scheduling again even after later or terminal state; stale or changed fresh preconditions fail. Stopping and starting the same namespace is the explicit way to load changed configuration. Adobe Experience Manager traffic remains inside the daemon and targets author only.
