# Pinned FSM Executable

Define a reusable path-only executable value and produce the FSM executable used by compatibility evidence from one development-owned verified source checkout. This task authenticates the FSM source snapshot and records the observed build invocation; it does not claim a hermetic or adversarially isolated supply-chain build.

**Steps:**

1. Commit the closed `slingshot.finite-state-machine-compatibility/1` `compatibility/finite-state-machine.toml` first with repository https://github.com/koraytaylan/fsm, commit 7d183e4d7a6b130343ea7d88897e0d029f604813, Model Context Protocol revision 2025-06-18, handler format fsm.handlers/1, exact `daemon_runtime_contract_format = "slingshot.daemon-runtime-contract/1"` plus the value from `policy/daemon-runtime-contract-1.sha256`, exact `author_agent_transport_contract_format = "slingshot.author-agent-transport-contract/1"` plus the value from `policy/author-agent-transport-contract-1.sha256`, the architecture's exact seven Cargo-home seed limits, and its exact registry-command-effect operation-key preimage/input/suffix limits and suffix inventory. Reject missing, additional, duplicate, reordered, differently valued, or fallback fields; this manifest is their sole Plan 0008 authority and cannot extend operation identity to maintenance controls.
2. Implement path-only `FiniteStateMachineExecutable` in `slingshot-test-support` with absolute-path, regular-file, and executable checks and no repository, source-build, configuration, daemon, or product dependency.
3. Implement `FiniteStateMachineCompatibilityPin` parsing and validation in `slingshot-development` with exact-length commit and supported-revision checks. Define `FiniteStateMachineCompatibilityIdentity` as the exact ordered FSM repository/commit, protocol revision, handler format, daemon-runtime format/digest, and author-transport format/digest tuple. Recompute both policy-manifest SHA-256 sidecars, compare repository and embedded typed bytes plus formats, and refuse a missing/malformed/stale digest without a local value or deployment override.
4. Implement a development command that accepts the explicit `SLINGSHOT_FINITE_STATE_MACHINE_SOURCE` checkout and, optionally, one explicit `SLINGSHOT_FINITE_STATE_MACHINE_CARGO_HOME_SEED` directory. Parse the source origin with a closed grammar accepting only canonical `https://github.com/<owner>/<repository>[.git]`, `ssh://git@github.com/<owner>/<repository>[.git]`, and scp-style `git@github.com:<owner>/<repository>[.git]`; require nonempty unescaped ASCII GitHub owner/repository segments, remove only optional terminal `.git`, and canonicalize to HTTPS for byte-for-byte pin comparison. Reject HTTPS user information, another SSH user/host, ports, queries, fragments, percent escapes, backslashes, empty/dot/extra segments, trailing slashes, and all other spellings. Then verify exact `HEAD`, index and tracked-worktree equality with that commit, no untracked paths, Cargo.lock presence, and the pin; reject every gitlink, submodule, path escape, or unsupported tree mode. If supplied, require an absolute existing directory and stream its valid-Unicode canonical relative paths in byte order under the manifest's exact component/path/depth, file/directory-count, per-file, and aggregate-byte limits. Apply the architecture's per-entry type/name/collision, path/depth, count, size, and mutation precedence; admit only ordinary directories and regular files, reject links/reparse/special/escaping/destination-aliasing/changing content before proportional copy or allocation, and record the complete content digest. This task does not assign the seed provenance.
5. Compute a canonical path/mode/blob digest of the verified commit and use the repository reader to export exactly that tracked tree into a new owner-only temporary source root. Verify the export immediately before the build, apply read-only permissions only as defense in depth, and build fsm-cli there with `cargo build --locked --target-dir <separate-temporary-target>`; never build in or write an output beneath the caller checkout. Start Cargo with a new private `CARGO_HOME` and target root, optionally seed that new home only from the explicit bounded directory, use an explicit resolved Cargo/Rust toolchain, and construct a closed child environment that removes Cargo configuration/source-replacement, compiler-wrapper, encoded/plain Rust flags, incremental, target-directory, and toolchain-selection injection variables before adding only the platform-required loader/tool variables. When a seed is supplied, require `--frozen --offline`; otherwise explicitly record that dependency acquisition may use the network. Record the Cargo/rustc verbose identities, linker identity, lockfile digest, allowed environment names and values, and seed digest or network mode.
6. Recompute the exported-tree digest after the build and reverify the caller checkout's exact `HEAD`, index, tracked worktree, and untracked-path state after success and every induced failure. Any observed source change fails and discards the executable. Ignored caller files are neither exported nor claimed as observed. Read-only permission bits and before/after digests are not represented as an operating-system isolation boundary against a malicious same-principal compiler or build script that restores bytes.
7. Resolve the resulting path into `FiniteStateMachineExecutable` from Cargo metadata and command output rather than a home, sibling-workspace, source-local target directory, or globally installed default.
8. Emit a machine-readable source-build observation containing the verified repository, commit, canonical before/after exported-tree digest, lockfile digest, protocol revision, handler format, both exact upstream contract formats/digests, observed toolchain/linker/environment/cache-or-network facts, and executable path. Label it explicitly as source-pin compatibility evidence plus exact workflow contract provenance, not complete dependency/toolchain provenance or reproducibility evidence; Plan 0009's release-input cache owns the stronger offline closure.

- The committed pin fixture parses to the exact required values.
- Canonical HTTPS, `ssh://git@github.com/koraytaylan/fsm`, and `git@github.com:koraytaylan/fsm` normalize to the same pinned repository; each form passes both with and without terminal `.git`. HTTPS user information, another SSH user/host, explicit ports, queries, fragments, percent escapes, backslashes, empty/dot/extra path segments, trailing slashes, and visually similar or case-changed owner/repository values fail.
- Wrong repository, commit, protocol revision, handler format, either upstream contract format/digest, policy bytes/sidecar/embedded-byte equality, index/tracked modification, untracked file, gitlink/submodule, unsupported mode, path escape, export-digest mismatch, missing lockfile, and missing executable each fail with distinct diagnostics.
- Paths containing spaces and a source checkout outside the Slingshot repository work.
- No test or implementation string contains /home, ~/Workspace, or a fixed sibling path.
- Development compatibility cases exercise the test-support path value and prove it rejects relative, missing, directory, nonregular, and nonexecutable targets without source-provenance logic.
- A development integration test against the real supplied checkout builds fsm-cli from a digest-verified private tracked-tree export into a separate temporary target directory, reports the exact commit/tree/lock/toolchain/environment/seed-or-network observation, recomputes the export digest, and proves the caller checkout's verified Git state is unchanged; an ignored-file fixture proves ignored bytes are outside the claim and absent from the export.
- An explicit matching Cargo-home seed supports frozen/offline compilation from an empty ambient Cargo home. Independently authored fixtures exercise zero, exact, and next-unit file count, directory count including the root, component bytes, canonical relative-path bytes, root-zero depth, per-file bytes, and checked aggregate bytes; non-Unicode, empty/dot components, destination aliases, linked/reparse/special/escaping content, and before/after mutation fail with the manifest's deterministic first-fault diagnostic before an over-bound copy or allocation. Absence of the seed remains a source-compatibility mode that records network acquisition and makes no dependency-byte provenance claim.
- Ambient Cargo source replacement, compiler wrappers, Rust flags, incremental/target roots, and toolchain-selection variables are absent from the build child; fixtures prove an attempted observed source mutation fails while the evidence text never upgrades permission bits or digest comparison into malicious-tool isolation, complete build provenance, or reproducibility.
