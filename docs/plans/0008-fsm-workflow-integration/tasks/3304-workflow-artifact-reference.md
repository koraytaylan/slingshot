# Workflow Artifact and Maintenance Result References

Prove workflow-facing operation artifacts and operation-free maintenance results retain their disjoint target-qualified access contracts inside exact structured envelopes without content bytes, paths, or remote secrets.

**Steps:**

1. Commit the artifact machine, stable workflow-store namespace, exact compatibility identity and pre-effect drift cases, package command, fake-author logical-operation/fence/duplicate-physical-record package and oversized ordinary structured result, post-success persistent-capacity and interrupted-transfer recovery, irrecoverable wrong-digest/retention result-unavailable cases, expected package access and exact `structured_result_artifact_access` outcome with deterministic `structured_result` slot, both authoritative-remote-success recovery/terminal envelope shapes, below-cap boundaries, keyless maintenance preview/apply handlers, surplus operation-key refusals, exact target/reviewed-digest applied-receipt replay, maximum complete maintenance preview and applied/replayed receipt externalization through exact operation-free association/access/metadata/read/lifecycle fixtures, synthetic non-Slingshot over-cap response, complete nested acknowledgement shapes, and forbidden-byte markers before implementation.
2. Define a machine that emits download_content_package and advances through the handler's success event.
3. Complete the exact upstream contract provenance gate before the starting event, then run the real FSM executor while FakeAuthor serves a package body with declared byte length and digest through one durable logical operation and at most one fenced command-effect attempt. Allow bounded duplicate physical records/attempts only when every losing consumer no-ops.
4. Require the target daemon to verify and publish the artifact before the Slingshot tool returns an access entry inside `structuredContent` containing `ArtifactDescriptor` plus `slingshot://profiles/{profile}/environments/{environment}/targets/{author_target_identity_digest}/operations/{operation_identifier}/artifacts/{artifact_identifier}`.
5. Exercise an ordinary command result too large for the inline disposition, require the daemon-created canonical JSON operation artifact in the deterministic `structured_result` slot and the exact operation-qualified `structured_result_artifact_access` outcome, and prove its envelope also remains an exact object below the cap. No other outcome tag or maintenance control may use the `structured_result` spelling.
6. Through real FSM control handlers, exercise over-inline maintenance preview and applied/replayed receipt values separately. Require both handler input schemas to reject `operation_key`, `workflow_effect_operation_key`, occurrence, operation identifier, and artifact identity. Preview uses only its exact selected target plus bounded criteria. Apply uses only that target plus the exact reviewed preview digest; byte-identical timeout retry/replay returns the same durable application receipt and retained associations, while changed target/digest conflicts without allocating a command logical operation or effect fence. Require only the exact `maintenance_result_access` outcome carrying direct target digest, `MaintenanceResultIdentifier`, preview/application kind, reviewed manifest digest, exact preview or receipt content digest, exact byte length, fixed `application/json`, association revision, exactly one current-preview or application-receipt retention owner, and `slingshot://profiles/{profile}/environments/{environment}/targets/{author_target_identity_digest}/maintenance/results/{maintenance_result_identifier}`. Reject any operation key, operation identifier, artifact identifier, artifact slot, path, `structured_result_artifact_access` tag, or operation-qualified URI in that branch.
7. After the real FSM produces and journals each maintenance access envelope, use a separate assertion against the production Plan 0007 server to read the retained URI through `resources/read`; this assertion never substitutes for the FSM preview/apply control attempt. Require the server first to issue target-and-identifier-only `MaintenanceResultMetadata`, validate the returned target, identifier, kind, reviewed source digest, content digest, exact byte length, fixed `application/json`, association revision, and retention owner against the access envelope, and then issue `MaintenanceResultRead` with that content digest. Require `MaintenanceResultStart` to repeat every identity-bound fact and permit between lookup and atomic read start only byte-identical metadata or the checked current-preview-to-application-receipt owner transition at the next association revision; every other change fails before start. Authenticate the complete operation-free `MaintenanceResultStart`/`MaintenanceResultChunk`/`MaintenanceResultEnd` same-handle stream and return the original canonical JSON document without reserialization. Prove preview replay and daemon restart preserve identifier/URI/bytes, apply transfers the matching preview association into application-receipt ownership, exact target/reviewed-digest apply replay preserves that receipt and its associations, a different current preview makes the superseded association unreadable, and explicit completed-receipt retirement atomically makes its preview and application-result associations unreadable.
8. While the remote-success command artifact remains obtainable, force persistent local capacity or an interrupted transfer and require daemon status to remain nonterminal `RecoveryRequired` with fieldless `RecoveryExecutionEvidence::AuthoritativeRemoteSuccess`, no operation certainty, no second logical operation or effect attempt, and no published descriptor. Resume the same acquisition through the existing identifiers; physical delivery/recovery records may duplicate only within the bound and must lose the already crossed effect gate.
9. Separately prove remote success followed by an irrecoverable required-artifact digest or retention failure yields `operation_terminal_error` kind `ResultUnavailable` with fieldless `TerminalFailureDisposition::AuthoritativeRemoteSuccess`, no certainty, and no descriptor. Require its exact envelope at `ack.result.structured` with absent `structured_sha256` and generic FSM failure handling rather than remote-failure authority.
10. Inspect real FSM history and journal output; require every conforming `ack.result.structured` value to equal its exact envelope with absent `structured_sha256`, and require absence of package, operation-slot `structured_result` document, maintenance-result document, filesystem-path, remote-location, and authentication bytes.
11. Feed the pinned FSM a separate synthetic response above its 4096-byte structured acknowledgement cap and pin the canonical prefix string at `ack.result.structured` plus digest at `ack.result.structured_sha256`; prove no conforming Slingshot envelope reaches this fallback.
