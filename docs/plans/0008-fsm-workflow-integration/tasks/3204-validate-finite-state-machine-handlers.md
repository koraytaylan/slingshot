# Validate FSM Handlers

Combine real FSM handler-format preflight with Slingshot-owned registry, template, registry-command operation-key/suffix, keyless maintenance-control, retry/timeout, and complete static-advance compatibility checks without pretending the pinned check output exposes fields that it omits.

**Steps:**

1. Commit valid and invalid expanded registry-command and maintenance-control handler fixtures paired with the real `fsm --json --data-dir <fresh> execute --check --handlers <private-snapshot>` outputs before implementing Slingshot validation. Include exact command-versus-control classification, required command key, forbidden maintenance-control key/operation/artifact identity, exact maintenance target/reviewed-digest arguments, source-byte, nesting-depth, handler-count, check-duration, standard-output, and standard-error boundaries; missing `--json`; leading, second, or trailing output; caller-path replacement during check; nonreturning and noisy children; fresh-data-directory isolation; hostile ambient FSM/home state; and cleanup. Pin that each current resolved-handler entry exposes `effect`, `kind`, `argv`, `timeout_ms`, Model Context Protocol `tool`/`arguments`, and `on_ok`/`on_failed` event names, but not `retry` or advance `payload`/`stamps`.
2. Bounded-read the caller table exactly once under `MAXIMUM_FINITE_STATE_MACHINE_HANDLER_SOURCE_BYTES = 1_048_576`; validate `MAXIMUM_FINITE_STATE_MACHINE_HANDLER_NESTING_DEPTH = 64` and `MAXIMUM_FINITE_STATE_MACHINE_HANDLER_COUNT = 256` before retained proportional allocation. Write those exact bytes into a newly created owner-only temporary directory, close and mark the file/tree read-only, and retain the original in-memory bytes as the sole Slingshot source.
3. For every invocation, create a distinct empty owner-only FSM data directory and distinct private home/configuration roots and run the caller-supplied real FSM executable with exactly `fsm --json --data-dir <fresh-path> execute --check --handlers <private-handler-snapshot>` inside the shared harness's supported-platform child-process containment. Construct the child environment from the harness's closed supported-platform allowlist: remove `FSM_DATA_DIR`; map `HOME`, `XDG_DATA_HOME`, `XDG_CONFIG_HOME`, `XDG_CACHE_HOME`, `XDG_STATE_HOME`, `XDG_RUNTIME_DIR`, `USERPROFILE`, `HOMEDRIVE`, `HOMEPATH`, `APPDATA`, `LOCALAPPDATA`, `TMPDIR`, `TMP`, and `TEMP` only to newly created private roots; drop every other inherited FSM/home/XDG/application-data/temporary selector; and retain only the exact platform-required loader/process variables. Concurrently drain output under `FINITE_STATE_MACHINE_CHECK_MAXIMUM_DURATION = 30 seconds`, `MAXIMUM_FINITE_STATE_MACHINE_CHECK_STANDARD_OUTPUT_BYTES = 8_388_608`, and `MAXIMUM_FINITE_STATE_MACHINE_CHECK_STANDARD_ERROR_BYTES = 1_048_576`; on deadline or either overflow, terminate the contained process tree and reap the direct child before returning a stable diagnostic or deleting private state. Require zero exit, empty standard error, and standard output consisting of exactly one pinned canonical JSON object plus one line feed with no byte-order mark, prefix, second value, or suffix. Treat that success only as the pinned FSM's handler-grammar, resolved-default, and rooted/literal-`argv[0]` validation for the copied bytes; it does not prove that the expanded executable exists, is regular, or is executable.
4. After successful preflight, parse the retained in-memory snapshot—not the caller pathname or temporary file—only to project the fields the pinned output omits. Require every Slingshot-compatible handler to declare all four retry members—`attempts`, `backoff_ms`, `max_backoff_ms`, and `on`—and require every present `on_ok` or `on_failed` advance to declare `payload` and `stamps` explicitly, including explicit empty values. Reject omission/default reliance rather than reproducing FSM defaults. For each explicitly declared source field also exposed by the check output, normalize only according to the pinned output fixture and require equality; validate all other exposed fields directly from that output.
5. Independently validate expanded `argv[0]` through the same supported-platform absolute-path, regular-file, and current-process executable-access predicate as `FiniteStateMachineExecutable`; reject missing paths, directories, Unix files lacking effective execute access, and Windows files lacking executable/access eligibility. Recompute both upstream policy sidecar digests and require exact repository/embedded/compatibility-manifest format/digest equality before accepting an effect-bearing table. Then classify each fixed tool name through Plan 0007's exact registry/control inventory and validate each argument-template placeholder and required literal. For a registry command handler, consume the compatibility manifest's exact nonempty/control-free UTF-8 namespace/request bounds, unsigned occurrence domain, fixed-order canonical JSON bytes, SHA-256/prefix key construction, exact base/final key byte bounds, and closed suffix inventory of empty plus `-backup-restore`; ordinary command effects may use only empty and the explicitly approved compensation command handler may use only `-backup-restore`. For `maintenance_preview` or `maintenance_apply`, reject `operation_key`, `workflow_effect_operation_key`, occurrence, operation identifier, and artifact identity; validate preview's exact target/criteria and apply's exact target/reviewed preview digest instead. Treat the maintenance-result resource URI as target/association-qualified and operation-key-free; its read path requires target-and-identifier-only `MaintenanceResultMetadata` before expected-digest `MaintenanceResultRead` and accepts only byte-identical association evidence or the sole checked current-preview-to-application-receipt owner/revision transition at read start. Contract provenance remains separate from both identity mechanisms.
6. Parse the check-output handler timeout into a typed bounded duration, reject unsupported Slingshot wait/deadline arguments, validate each source-projected retry class/policy against the scenario contract, and validate complete static advance event/payload/stamp values as bounded and authority-neutral. A registry-command retry must retain its exact operation key. A maintenance-apply retry must instead retain byte-identical target/reviewed-digest arguments and accept only durable applied/replayed receipt plus association equality; it never allocates or validates a workflow operation key. No `on_failed` advance may assert a Slingshot terminal disposition or directly request compensation.
7. Produce field-specific diagnostics that distinguish source/input bounds, private-data/home construction, check deadline/output bounds, real FSM preflight failure, malformed or mismatched check output, forbidden default reliance, and Slingshot compatibility failure; remove every private handler/data/home copy only after the child is reaped.

**Tests:**

- The real pinned executable accepts the valid fixture before Slingshot registry checks run.
- Golden output from that executable proves the exact global-flag command line, one-object-plus-line-feed JSON framing, exposed-field list, and omission of retry plus advance payload/stamps; missing `--json`, human output, nonempty standard error, a byte-order mark, prefix, second value, or trailing bytes fail. A pin whose output shape changes requires an explicit compatibility update.
- Replacing or deleting the caller pathname after the one bounded read cannot change either FSM input or Slingshot projection; the check output and source-only fields always describe the same byte snapshot.
- Exact source/depth/count/output boundaries pass, the next unit fails before proportional retention, and nonreturning/noisy helpers—including a descendant that retains an output handle—have their contained process tree terminated and direct child reaped under the named deadline/caps with no private copy left behind.
- Unknown tools are accepted or rejected according to actual FSM behavior, then are always rejected by the Slingshot registry check; no test claims FSM owns Slingshot tool knowledge.
- A missing, directory, nonregular, or platform-nonexecutable expanded `argv[0]`; independently stale/malformed/missing daemon-runtime or author-transport format/digest in policy bytes/sidecar/embedded/manifest provenance; missing/flexible tool names; malformed placeholders; empty/control/over-bound workflow namespace or instance request identifier on a registry command; occurrence overflow; noncanonical key preimage; malformed base key; unknown/over-bound/wrong-handler suffix; timeout bound; missing registry-command workflow-effect operation key; surplus maintenance-control key/occurrence/operation/artifact identity; missing or changed maintenance target/reviewed digest; unsupported wait argument; invalid retry policy; incomplete retry object; omitted advance payload/stamps; authority-bearing failure payload; and direct-compensation failure event each fails with a distinct Slingshot diagnostic. Exact/next command-key input bounds, occurrence zero/maximum/overflow, composed-versus-decomposed Unicode, alternate member/escape/integer spellings, both allowed suffixes, digest/key independence, retry/restart/namespace/occurrence separation, keyless maintenance apply replay, and changed target/digest conflict match independent vectors.
- Validator output states that stable store-namespace ownership and cross-occurrence runtime uniqueness are workflow invariants because the pinned FSM has no internal store/effect identifier placeholder.
- The validator compares exactly the fields the pinned check output exposes, projects retry and complete advances only from the same retained bytes accepted by that check, rejects all implicit defaults for those omitted fields, and fails an exposed source/output mismatch.
- Preseeded dead letters and configuration under ambient `.fsm`, `FSM_DATA_DIR`, every named Unix XDG/home/temporary root, and every named Windows profile/application-data/temporary root are never read, changed, or reflected in check output; simultaneous checks receive unequal explicit empty data directories, and success, failure, timeout, and output overflow remove each private data/home root only after reap.
