# Expose Operation Resources

Expose target-partitioned durable operation state, result, artifact metadata, and operation-free maintenance-result JSON through stable resource templates backed by bounded daemon snapshots and verified streams.

**Steps:**

1. Commit bounded listing, continuation, template, read-contents, encoding, target-partition, absent/pending operation, artifact metadata, secret-exclusion, and exact result-resource provenance fixtures including revised closed semantic failures and independent stale author-agent-transport/canonical-contract/wire-name/version/limits/argument-schema/result-schema cases. Add maintenance-result fixtures for a fresh protocol process with no prior tool response or cache, current externalized preview, unchanged metadata-to-read start, the sole exact-apply owner/revision transfer between lookup and start, transfer after same-handle read start, externalized applied/replayed receipt, daemon reconnect/restart, supersession or retirement before read start, missing/corrupt bytes, wrong target, malformed identifier, and every kind/reviewed-source/content/length/media/owner/revision mismatch. Include transport-digest-only and contract-artifact-only drift with fixed five-field identity and role bytes/digests, plus an argument-schema-only mutation whose result schema and every other identity field remain byte-identical.
2. Implement canonical percent encoding for `slingshot://profiles/{profile}/environments/{environment}/targets/{author_target_identity_digest}/operations/{operation_identifier}` state/result descendants and `artifacts/{artifact_identifier}` descendants. Advertise the separate exact template `slingshot://profiles/{profile}/environments/{environment}/targets/{author_target_identity_digest}/maintenance/results/{maintenance_result_identifier}` with media type `application/json`; its identifier is Plan 0004's exact 64-lowercase-hexadecimal operation-free type and cannot accept an operation, command, artifact, or slot component.
3. Implement paginated operation listing through Plan 0004's bounded `ListOperations` service; current requests default to the current author-target partition while explicit operation resource URIs preserve historical partitions. `resources/templates/list` includes the exact maintenance template; concrete maintenance links come only from a daemon result association and do not require an invented operation-list row.
4. For result resources, require exact current `AuthorAgentTransportContractDigest`, load the durable operation's complete five-field `SelectedCommandContractIdentity`, compare exact wire name/`1.0.0`/limits/argument-schema/result-schema digests with the current authenticated registry descriptor, authenticate exact canonical-contract bytes against the manifest and both root annotations, and verify both annotated role-schema bytes against their digests. Validate raw command-result bytes under `slingshot.command-canonical-json/1`, then ordinary Draft 2020-12 decoded result shape, then typed closed success/failure before returning revision-valid `contents`. Reject independent transport, contract, or identity drift, wrong-stage acceptance, aliases, arbitrary failures, and unknown/surplus fields as closed resource errors. Artifact resources remain metadata-only with no bytes/path.
5. For a maintenance read, require the canonical profile/environment, direct `AuthorTargetIdentityDigest`, and `MaintenanceResultIdentifier`, then invoke Plan 0004 `MaintenanceResultMetadata` keyed by exactly that target and identifier. Verify the returned target, identifier derivation, preview-versus-application kind, reviewed source digest, content digest, exact length, `application/json`, association revision, and current-preview/application-receipt retention owner; use that authenticated non-invertible content digest as the expected digest in `MaintenanceResultRead` for the same target and identifier. Consume only `MaintenanceResultStart`/`Chunk`/`End`. Require Start target, identifier, kind, reviewed source, content digest, length, and media to equal the lookup; require owner/revision to equal it except for the sole current-preview to application-receipt transition at the checked next revision when exact apply commits between calls. Verify identifier derivation plus the complete actual stream length/digest and unchanged same-handle evidence, and return exactly one `TextResourceContents` whose URI is the request URI and whose text bytes are the original canonical JSON without reserialization. Do not recover the digest by hash inversion, a prior tool result, a process cache, a URI member, or an extra read identifier. Any other change, refusal, mutation, or mismatch returns a closed resource error and no partial `contents`.
6. Assert operation and maintenance read values remain stable across daemon reconnect/restart and a fresh Model Context Protocol process. A supersession, retirement, or disappearance committed before atomic read start yields no `MaintenanceResultStart`; a lifecycle change ordered after same-handle read start cannot alter its authenticated stream snapshot. A current preview remains readable until exact apply transfers ownership or another preview supersedes it; exact apply replay and restart retain both receipt-owned preview/application associations; later explicit completed-receipt retirement makes both unreadable atomically for subsequent reads. No resource contains a publisher address, authentication material, filesystem path, or fabricated operation identity; tool content may duplicate the access URI as a resource link.

**Tests:**

- `model_context_protocol_resources` pins all operation templates, the exact target-qualified maintenance-result template, paginated operation descriptors, revision-valid operation and maintenance read contents, target partitions, and artifact metadata resources in both protocol eras.
- Maintenance lifecycle cases prove fresh-process target-and-identifier metadata lookup, unchanged and sole-apply-transfer read starts, current-preview read, transfer after read-start linearization, applied/replayed receipt read, restart-stable bytes, supersession or retirement before start, every metadata/start/integrity refusal, no partial contents, and exact canonical text/content digest. Reconnect and secret cases prove resources expose durable nonsecret state only without process cache or hash inversion.
- Result-resource bytes for every revised semantic failure equal the owning tool/CLI envelope facts; a resource cannot widen a command's output schema, accept a failure from another command/version, treat unchanged result schema as compatibility when argument-schema digest alone drifted, or accept transport/contract-only drift because the five durable fields still match.

- **Done when:** `cargo test -p slingshot-command-line --test model_context_protocol_resources` proves bounded target-qualified operation resources authenticate author-agent-transport and canonical-contract/annotation provenance around all five durable command-identity fields, while the operation-free maintenance template/read path resolves an otherwise non-invertible digest through exact target-and-identifier metadata, authenticates Start and the same-handle stream under only the checked apply-transfer race, and remains lifecycle-correct through fresh process, supersession, and retirement; transport/contract/argument-only drift, corruption, aliases, partial contents, bytes/paths/secrets in artifact metadata, cache/hash-derived identity, and invented operation identity all remain impossible.
