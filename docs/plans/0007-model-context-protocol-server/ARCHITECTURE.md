> The dual-revision transport, generated registry projection, and durable operation behavior.

## 0029 — Standard Input And Output Transport

`StandardStreamProtocolTransport` reads one bounded UTF-8 line at a time, rejects embedded carriage returns, duplicate object keys, invalid JSON-RPC envelopes, forbidden client responses, and resource-limit violations, then converts external `id` values into a typed `RequestIdentifier`. `ActiveRequestRegistry` atomically reserves that identifier before handler creation under `MAXIMUM_MODEL_CONTEXT_PROTOCOL_ACTIVE_REQUESTS`. A duplicate active identifier is rejected without dispatch, replacement, detachment, or mutation of the original request. A distinct request above the active limit is rejected without dispatch by one bounded resource-limit JSON-RPC response; failure to enqueue or write either rejection enters ordinary output fail-stop. Identifier reuse is accepted only after the preceding reservation's release point.

An ordinary request reservation remains active through handler completion and response enqueue and releases only after `ProtocolOutputWriter` confirms the complete newline-terminated response was written. A cancellation releases only after response suppression and local waiter/progress detachment are atomically installed. End of input or output failure releases all reservations only after their detach/suppression cleanup linearizes. Thus a silent attached request consumes one slot, a queued terminal response still blocks duplicate reuse, and cancellation/terminal/output races cannot dispatch two handlers for one active identifier.

End of file stops intake, detaches local waiters, drains already-formed responses through a named ordinary-shutdown deadline, and exits. `ProtocolOutputWriter` is the sole owner of stdout. Each producer canonically serializes a complete newline-terminated line within the message bound before enqueueing it. The queue is bounded by `MAXIMUM_MODEL_CONTEXT_PROTOCOL_OUTPUT_QUEUE_MESSAGES` and `MAXIMUM_MODEL_CONTEXT_PROTOCOL_QUEUED_OUTPUT_BYTES`; concurrent producers wait for capacity only through `MODEL_CONTEXT_PROTOCOL_OUTPUT_QUEUE_PRESSURE_DEADLINE`. The writer allows one complete buffered line to make progress only through `MODEL_CONTEXT_PROTOCOL_OUTPUT_WRITE_DEADLINE`. Responses and notifications therefore never interleave.

Queue-pressure expiry, output-write expiry, and closed or failed stdout all enter one idempotent output-failure transition. It stops request intake, rejects new output, closes the producer queue, discards queued lines whose write has not begun, detaches every local operation waiter/progress subscription, releases the active registry after detach/suppression, and sends no daemon or agent cancellation. Cleanup completes within `MODEL_CONTEXT_PROTOCOL_OUTPUT_FAILURE_SHUTDOWN_DEADLINE`; the application waits for neither a blocked writer worker nor a blocked input reader beyond that bound and exits with Plan 0006's local transport failure classification. A line not yet started contributes no bytes. If the operating-system sink accepts a prefix and then blocks or fails, the writer closes stdout permanently, writes no newline or later byte, and exits; clients treat that single trailing unterminated prefix as a transport failure, never as a protocol message. Every preceding newline-terminated line remains complete and valid. This fail-stop rule is deterministic for slow, full, and closed output and is the only admitted partial-sink case.

`ProtocolDiagnosticSink` owns stderr independently of protocol output. Producers format one bounded redacted record, attempt a zero-wait enqueue into named message/byte bounds, and drop it with a saturating in-memory loss count when the queue is full or closed. Its writer may be abandoned on blocked or closed stderr; ordinary and fail-stop shutdown never synchronously writes a diagnostic, waits for diagnostic capacity, joins a blocked writer, or invokes a panic path that does so. Diagnostic delivery is best effort and can neither consume an active-request/output slot nor extend any protocol deadline.

Normal end of input drains complete queued lines only through the ordinary shutdown deadline. If queue pressure or a write deadline expires during that drain, output-failure shutdown supersedes normal drain. Concurrent end-of-input, cancellation, terminal completion, producer enqueue, writer acknowledgement, and output failure converge through the same once-only shutdown coordinator: intake remains stopped, every waiter detaches at most once, each request reservation releases exactly once at its defined point, no post-failure line begins, and durable operation state is unchanged.

The handler validates protocol version, client identity, and capabilities from `_meta.io.modelcontextprotocol/*` on every request. A syntactically modern request naming any revision outside the two-item authority selects the modern era and receives exact `UnsupportedProtocolVersionError` code `-32022` whose data is `{"supported":["2026-07-28","2025-06-18"],"requested":<exact requested string>}`. A schema-valid request for a server method or capability outside the advertised inventory receives `MethodNotFoundError` code `-32601`, never malformed-input or missing-client-capability classification. The remaining emitted modern error inventory is exactly JSON-RPC `ParseError` `-32700`, `InvalidRequestError` `-32600`, `InvalidParamsError` `-32602`, and `InternalError` `-32603`; standard-stream operation has no header-mismatch branch, and no implemented action requires a client capability, so `HeaderMismatchError` and `MissingRequiredClientCapabilityError` are unreachable. A direct request without structurally valid modern metadata is era-ambiguous and fails before semantic dispatch. For revision `2025-06-18`, `LegacyInitializedRevision` requires `initialize` as the first request and negotiates only legacy session semantics. An unselected process chooses the modern era from `server/discover` or structurally valid modern per-request metadata even when the requested version is unsupported, and chooses the legacy era from the first structurally valid `initialize` request before legacy version negotiation. Once selected, it never falls across eras. Both paths share framing, registry projection, execution, and one semantic payload model. Revision decorators transform that semantic payload into era-valid response members: modern required members are added only by the modern decorator, and the legacy decorator omits them. The complete unmodified official schema artifact for each revision is committed with source location, immutable retrieval identity, cryptographic digest, and exact bytes. Every positive inbound request/notification fixture validates against its applicable official definition before the implementation handles it; every deliberately malformed inbound fixture is rejected by that definition, while schema-valid unsupported modern versions, unsupported methods/capabilities, and legacy fallback negotiation remain their exact error or successful-negotiation cases rather than being mislabeled malformed. Every emitted response validates against its applicable official definition. Only after both-direction validation may golden sessions normalize semantic payloads and compare eras.
