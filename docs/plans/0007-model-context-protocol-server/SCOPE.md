# Plan 0007 — Model Context Protocol Server

> Project the same operation registry and daemon state used by the command line onto a byte-clean standard-input/standard-output server for both modern stateless and fsm-compatible initialized clients.

## Why this plan

Slingshot is an automation tool as well as a human command. A Model Context Protocol host needs discoverable typed tools, durable operation resources, progress, and cancellation behavior without learning the local daemon protocol. Rewriting those schemas by hand would let the command line, agent protocol, and model-facing surface disagree. The server therefore derives its tools, input schemas, annotations, result schemas, and operation resources from the shared registry and maps every call through the same namespaced daemon.

The current Model Context Protocol revision uses stateless per-request metadata and newline-delimited standard-stream messages: [Model Context Protocol transports, revision 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports). The fsm executor requires the earlier connection lifecycle whose first exchange is `initialize` followed by `notifications/initialized`: [Model Context Protocol lifecycle, revision 2025-06-18](https://modelcontextprotocol.io/specification/2025-06-18/basic/lifecycle). Slingshot's sole preference-ordered supported-revision list is exactly `["2026-07-28","2025-06-18"]`; modern discovery and unsupported-version errors expose that order, while a schema-valid legacy initialize request for another version successfully offers `2025-06-18` under the legacy negotiation rule. Each era has its own byte transcript and exact supported method/capability/error inventory.

## In scope

- **0029 — Standard Input And Output Transport.** Register the exact thirteen-leaf compiling protocol-module inventory once, parse and serialize bounded newline-delimited JSON-RPC messages with one stdout writer, own a bounded active-request registry with duplicate/saturation/release semantics, fail-stop within named queue-pressure/write/shutdown deadlines when output cannot progress, keep stderr diagnostic writes nonblocking and drop-capable, detect the protocol era, pin the exact ordered two-revision authority plus each complete official schema, validate both inbound request/notification acceptance or rejection and outbound responses, and implement the closed modern discovery/error inventory plus correct legacy initialize fallback negotiation.
- **0030 — Registry-Derived Surface.** Generate command tools/resources from each exact `1.0.0` command schema plus canonical limits digest; derive the exact five-required/seven-optional `operation_key` policy from `IntrinsicIdempotencyClassification`; authenticate exact `slingshot.author-agent-transport-contract/1` and `slingshot.command-canonical-json/1` bytes, the latter through the schema manifest and both `x-slingshot-canonical-json-contract-sha256` annotations without changing the five-field durable identity; validate raw command bytes before Draft 2020-12 decoded shape and typed construction; reject independent provenance/schema/contract drift; preserve complete over-inline maintenance bytes through Plan 0004's operation-free target-qualified maintenance-result association and exact Model Context Protocol template/metadata/read lifecycle without hash inversion or process cache; preserve canonical phrase/asset/token requests; expose only command-specific closed result/failure shapes; and prove byte-identical command-line/Model Context Protocol structured outcomes alongside the existing controls, recovery evidence, and size bounds.
- **0031 — Live Operation Coordination.** Authenticate exact `slingshot.daemon-runtime-contract/1` on every versioned local request, preserve a supplied operation key or generate an omitted optional key exactly once before the first request and retain it across every in-request reconnect/retry, submit and observe operations through the selected daemon, preserve execution-certainty versus authoritative-remote-success recovery evidence, resume current-target paused recovery with optimistic revision comparison, distinguish command execution from observation error semantics, keep attached calls until terminal/cancellation/end-of-input across local reconnects, emit correlated progress, make cancellation or process loss detach local observation, compose the executable server entry, pin both revisions with byte-exact sessions, and prove process stdout/secret hygiene plus current-nonce or retained-instance-handle cleanup without process-identifier signaling races.

## Out of scope

Streamable Hypertext Transfer Protocol transport, server-initiated Model Context Protocol requests, prompts, sampling, elicitation, direct Adobe Experience Manager traffic, publisher access, and semantic cancellation of Sling Jobs are excluded. Closing standard input shuts down the server process but does not stop durable daemon operations. A cancellation notification abandons the local request and its progress stream; it does not cancel the underlying job.

## Launch and compatibility contract

The server is launched for one selected namespace only as `slingshot model-context-protocol serve --profile <name> --environment <name>`. The leaf rejects `--output`, `--detach`, `--operation-key`, and ordinary operation/target-override options. The top-level command application selects and composes the server, uses Plan 0006 exact runtime-digest/target/revision-checked daemon startup plus exact current transport-digest provenance, and then owns standard input and standard output until end of file. A `server/discover` request or structurally valid current per-request metadata selects modern semantics, including the exact `-32022` unsupported-version response whose `supported` value is `["2026-07-28","2025-06-18"]`; an initial schema-valid `initialize` selects legacy semantics and either echoes `2025-06-18` or successfully offers it for an unsupported requested version before awaiting `notifications/initialized`. Era-conflicting messages fail deterministically. Every stdout line is one valid protocol message and contains no embedded newline. Diagnostics and nonprotocol logging use only the bounded nonblocking/drop-capable stderr sink.

Both eras carry one semantic fourteen-tag `MachineOutcomeEnvelope` shared byte-for-byte with command-line JSON, including the exact registered semantic failure object without aliases or lost fields; revision handlers add only required wire decoration. Tool/resource schema provenance binds all five fields—wire name, exact `1.0.0`, command-limits digest, argument-schema digest, and result-schema digest—and separately authenticates the exact canonical-JSON contract digest through its manifest and role-schema annotations before serving the surface or a durable operation result resource. Plan 0004 maintenance results instead use the exact operation-free target-qualified `slingshot://profiles/{profile}/environments/{environment}/targets/{author_target_identity_digest}/maintenance/results/{maintenance_result_identifier}` template; read first resolves target-and-identifier-only metadata to obtain the expected content digest, then revalidates the full start and same-handle stream under the unchanged-or-sole-apply-transfer rule before returning the original canonical `application/json` text. Supersession or explicit receipt retirement before read start removes readability without an operation identity. The command-contract digest relationship does not add a sixth durable identity field. All four command-line signal-only local-error variants are not Model Context Protocol outcomes and satisfy no tool output schema. Modern revision `2026-07-28` includes `resultType: "complete"` on every successful JSON-RPC result, including a successful JSON-RPC `tools/call` response whose tool outcome has `isError: true`. Resource list/read results include required cache/scope/response metadata; legacy responses omit modern-only members.
