# Storage Fault Chaos

SQLite and artifact failures must preserve the last complete fact rather than silently creating a fresh store, a partial transition, or a successful corrupt result.

**Steps:**

1. Commit exact/mutated `slingshot.daemon-runtime-contract/1` bytes/digests, pinned SQLite source/build/configuration evidence, closed SQL-inventory and restrictive-VFS reports, databases, every allowed and forbidden SQLite object/open class, poisoned ambient-temp canaries, artifacts, diagnostics, staging sidecars, publication receipts, and failure schedules first. Include independent primitive/formula vectors for the 32-byte WAL header, 24-byte frame header, transaction growth, 67,502,112-byte WAL, 50,626,592-byte high-water, 1,141,506,080-byte active physical maximum, and 2,215,247,904-byte replacement aggregate/equal reserve. Include every typed physical-storage boundary and existing failure plus signals/crashes/output loss immediately before, at, and after non-overwriting atomic artifact publication; the gap after publication before published-state synchronization; and before, during, and after final success-render acknowledgement.
2. Implement deterministic test support using the exact pinned SQLite source/build, real limits/locks, a restrictive delegating VFS open oracle, poisoned ambient temporary paths, and temporary filesystem permissions where portable, with an equivalent scripted adapter only for explicitly unsupported platform-specific filesystem gaps. Before SQLite initialization require `SQLITE_CONFIG_STMTJRNL_SPILL = -1`; require compile option `TEMP_STORE=3` and runtime `PRAGMA temp_store = MEMORY`. Emit a canonical row/operating-system capability report that distinguishes every real native filesystem case from an explicitly unsupported policy-fixture branch; no adapter can substitute for SQLite source/build/configuration, SQL-inventory, VFS, or no-spill evidence.
3. Exercise open, contract authentication, Plan 0004 and Plan 0005 migrations, exact physical-object whitelist and replacement-main policy, physical-file validation/checkpoint/backpressure recovery, admission, progress/retry transition, agent submission/event/reconciliation/terminal settlement, and artifact installation. The closed parameterized SQL inventory must reject dynamic SQL, `ATTACH`, `DETACH`, `VACUUM`, `VACUUM INTO`, temp-schema objects, caller pragmas, unbounded materialization, and every unlisted disk-transient path; the VFS must reject rollback/master/replacement sidecars and every temporary/transient/subjournal/super-journal/delete-on-close/unknown/outside-root open. For resumed reads use one verified handle at offsets zero, one, length minus one, and length; hash/discard the prefix before `ArtifactStart`; mutate/replace the path, discarded prefix, and emitted suffix; and require no successful end or publication on mismatch. For CLI destination publication, retain the exclusive lock and exact ready/published receipt through final renderer acknowledgement. Pre-publication loss leaves only self-consistent resumable private state; publication is the success linearization point; post-publication loss followed by an identical invocation must authenticate a no-follow same-handle regular destination against every receipt identity/length/digest and re-render the original success without daemon artifact read, resume, second publication, or collision. A missing/mismatched receipt or destination fact remains a non-overwriting collision. Exercise the maximum complete maintenance manifest inline and the first over-inline complete preview/applied/replayed document through its operation-free `maintenance_result_access` association, target-plus-identifier `MaintenanceResultMetadata` lookup, and `MaintenanceResultRead` stream, including exact identifier/metadata/owner/URI, metadata-supplied expected digest, closed unreadable refusal, apply transfer, replay, supersession, and retirement without hash inversion, truncated effects, or an invented operation artifact.
4. Reopen independently, run integrity and foreign-key checks, and compare a canonical export of all durable facts plus exact artifact bytes against the complete-before or complete-after expectation. Do not infer transaction atomicity from SQLite database, write-ahead-log, or shared-memory container byte identity.
5. Ensure unsafe or newer store open prevents service readiness, reports one bounded diagnostic rather than replacing the store, and leaves every input database byte-identical.

**Tests:**

- Each injected write failure commits the whole intended fact or preserves the exact previous canonical durable state, and every reopened database passes integrity and foreign-key checks.
- Agent job event and subscription cursor/digest facts commit together or neither changes; an allowed untracked event commits only its independent cursor/digest fact.
- Busy conditions respect the named bound and leave the daemon responsive after release.
- Independently calculated vectors prove database `4,096 * 262,144 = 1,073,741,824`, maximum-transaction WAL growth `4,096 * (24 + 4,096) = 16,875,520`, WAL `32 + 16,384 * (24 + 4,096) = 67,502,112`, high-water `67,502,112 - 16,875,520 = 50,626,592`, active physical `1,073,741,824 + 67,502,112 + 262,144 = 1,141,506,080`, and replacement/equal reserve `2 * 1,073,741,824 + 67,502,112 + 262,144 = 2,215,247,904`. Exact maxima pass; the next unit, one maximum transaction at/above high-water, overlong reader, failed/busy/late checkpoint, and still-over-high-water state keep writes backpressured and readiness or mutation refused exactly as the typed daemon-runtime contract requires.
- Exact SQLite source/build, pre-initialization statement-journal no-spill configuration, compile-time and runtime memory temp store, closed bounded SQL/query-plan inventory, and restrictive VFS whitelist all authenticate before mutation. Statement journals, sorts, transient indexes, materialized results, and temporary databases create no disk object even when every ambient temporary path is trapped; every forbidden statement/open or unavailable invariant refuses readiness unchanged.
- Newer or corrupt databases are not migrated, truncated, or replaced.
- Missing, partial, and mismatched artifacts never return success; before terminal settlement, proven remote success preserves only fieldless authoritative-remote-success recovery or result-unavailable evidence and never gains certainty.
- Destination, staging, sidecar, symbolic-link, and hard-link attacks preserve the pre-existing destination and cannot publish attacker-selected bytes.
- Offset-zero/one/length-minus-one/length resumes authenticate the complete prefix on the same handle before the first response; prefix/suffix mutation, truncation, and path replacement never yield successful `ArtifactEnd` or publication.
- Before-publication interruption publishes no destination and remains resumable. At/post-publication signals cannot select interruption or resume. Forced output/process loss after publication preserves the exact receipt, and an identical fresh process truthfully re-renders exit-0 success without remote access, publication, or collision; receipt/destination mismatch preserves the existing destination as a collision.
- Maintenance never removes a nonterminal operation, retained result, or referenced artifact; the complete maximum-inline value and first-over-inline preview/applied/replayed values preserve every effect and canonical byte through the exact operation-free association/metadata/read contract. The authenticated target-plus-identifier metadata lookup either supplies only the exact returned target/identifier/kind/reviewed-source/content/length/media/revision/live-owner fields or refuses unreadable with no partial metadata before a read, and no case inverts the identifier hash. Read start accepts only unchanged identity-bound metadata or the sole current-preview-to-application-receipt owner/revision transition; transfer after read start preserves the acquired same handle, and every other transition refuses. Identifier derivation and all association metadata remain valid across checked-next-revision apply transfer and revision-stable replay; supersession and completed-receipt retirement release only the contract-selected associations, and interrupted apply is replay-safe.
- Restart after every recoverable fault reaches the same state as reopening the retained durable prefix.
- Every supported native row emits the exact real-versus-policy case inventory; task `release-artifact-contract` reruns the real storage/artifact-substitution subset and binds that report into authenticated row evidence.

- **Done when:** `cargo test -p slingshot-development --test storage_fault_chaos` authenticates the daemon-runtime contract and passes the independently calculated WAL/disk/replacement/reserve vectors, exact pinned SQLite no-spill/closed-SQL/restrictive-VFS policy, every physical checkpoint/backpressure case, same-handle remote resume, publication-versus-render-receipt race, receipt-backed success re-render, complete operation-free maintenance-result association/metadata/read lifecycle, and filesystem schedule with truthful non-collision outcomes and restart equivalence, and `scripts/quality` succeeds.
