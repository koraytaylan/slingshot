# Credential Exposure Threat Suite

Redacted display implementations are only one route by which secrets can escape. This task follows distinct credential sentinels through the complete process and scans every unintended observable byte surface.

**Steps:**

1. Commit distinct 64-byte high-entropy ASCII sentinels first for every role-unknown configuration-source document, password, private key, client secret, signed assertion, access token, authorization header, continuation HMAC key material, and Open Service Gateway Initiative properties classified sensitive by metatype or the pinned name policy, plus malformed classification and malicious remote errors that reflect supplied values. Add lifecycle sentinels distinguishing temporary `SensitiveConfigurationDocument` bytes from long-lived extracted `SecretValue`, private comparison digests, source references, profile/environment names, unknown keys/values, parser excerpts, and dependency causes. Place configuration sentinels in scalar, primitive-array, scalar-array, Collection, empty, null, mixed, nested, type-disagreed, invalid-Java-Unicode, case-folded-duplicate-key, and over-bound carriers. Sentinels use only the unreserved Base64 URL alphabet, carry no shared class prefix, and are mapped to classes outside their bytes. Before injection, require that no two classes share a scan needle and no needle occurs in the fixed redaction marker, labels, fixed public diagnostic vocabulary, or captured nonsecret baseline.
2. Build capture support for display/debug, chained errors, tracing, panic reports, command-line output, Model Context Protocol output, workflow acknowledgement and journal output, bounded daemon diagnostics, process arguments, local frames, SQLite files, artifact metadata, and retained test diagnostics.
3. Drive Basic and Cloud authentication through both per-file attempts, both whole-generation attempts, role inventory and S2 equality, selected-source parsing, assertion construction, Identity Management Services exchange, author submission, sensitive and malformed configuration-inspection results, continuation validation, failure, retry, terminal result, daemon restart, and command-line, Model Context Protocol, and workflow queries. Verify `SensitiveConfigurationDocument` owns every source only through digest/inspection/selected-parse calls, has redacted formatting and no serialization/equality/hash/order/clone/general byte interface, disposes its owned mutable buffer, and cannot survive snapshot construction. Verify only extracted password/key/client-secret/assertion/token values enter `SecretValue`, which remains redacted and narrowly lends bytes. Instrument the fake-agent configuration trace after exact instance selection and before any carrier/value method, exception conversion, or result allocation. It requires exactly one successfully acquired `MetaTypeService`; one nonempty configuration bundle location matching exactly one non-uninstalled bundle; null factory PID with the requested instance PID exactly once in `getPids()` and zero times in `getFactoryPids()`, or a nonempty valid factory PID exactly once in `getFactoryPids()` and zero times in `getPids()` while retaining instance identity; exactly one `getObjectClassDefinition(selected_pid, null)` call with no locale fallback/raw Designate parse/guess/cross-bundle lookup; and exactly one Unicode-15.1-default-fold-plus-NFC property-key match in complete `AttributeDefinition.ALL` evidence. Map exact `PASSWORD` to Password, the nine exact primary types to their corresponding NonPassword scalar identities, and `BIGINTEGER`, `BIGDECIMAL`, unknown, absent, duplicate, contradictory, disappearing, or failed evidence to Unavailable before any value access.
4. Permit credential bytes only inside the explicitly captured outbound authentication field at its intended identity or author endpoint; dispose of that capture before scanning every other channel.
5. Define the closed versioned `SECRET_SCAN_TRANSFORMS_V1` inventory as identity bytes, ASCII lowercase, ASCII uppercase, lowercase hexadecimal, uppercase hexadecimal, RFC 4648 standard Base64 padded and unpadded, RFC 4648 URL-safe Base64 padded and unpadded, percent encoding of every byte with uppercase and lowercase hexadecimal triplets, RFC 8259 JSON string-content escaping without outer quotes, and `application/x-www-form-urlencoded` encoding. Set `MINIMUM_SECRET_SENTINEL_FRAGMENT_BYTES = 16`. For every sentinel and transform, scan the complete transformed value, the transform of every contiguous raw slice of at least 16 bytes, and every contiguous window of the full transformed value at the exact transform threshold: 16 bytes for identity/case/JSON/form, 32 for hexadecimal, 22 for Base64, and 48 for percent encoding. Deduplicate needles byte-for-byte; no Unicode normalization, compression, hashing, encryption, unspecified encoding, fuzzy match, or shorter fragment is part of the claim.

**Tests:**

- Each intended endpoint receives the correct authentication material and no unintended endpoint receives any credential.
- No complete sentinel or closed-inventory encoding of any contiguous fragment at the exact 16-raw-byte threshold appears in any captured diagnostic, output, argument, local message, database, artifact metadata, or panic report.
- Malicious reflected remote errors remain bounded and redacted through every source chain. Public configuration diagnostics contain only their five manifest fields, use the inclusive 32-item truncation marker, and expose no source reference or source-ordering oracle.
- A selected source can move from temporary `SensitiveConfigurationDocument` into typed values only after equal S2; only extracted secret members become long-lived `SecretValue`. Neither wrapper leaks through formatting, serialization, equality/hash/order, parser error retention, replacement, or drop; the suite claims zeroization only for Slingshot-owned mutable buffers.
- A metatype-sensitive or policy-sensitive configuration property becomes the typed redacted value before persistence and cannot reach any machine envelope or workflow acknowledgement as plaintext; malformed classification is rejected without persistence.
- Password, unavailable-metatype—including zero/multiple/failed providers, absent/duplicate/opposite ordinary/factory inventory, invalid factory PID, zero/multiple/disappearing bundle-location matches, failed or duplicate object-class/attribute evidence, non-null-locale/fallback attempt, `BIGINTEGER`/`BIGDECIMAL`/unknown type, or any ambiguity—and sensitive-name cases perform zero carrier/value reads and reveal no key, type, carrier, length, hash, filter, reflected exception, or hint. Visible NonPassword controls preserve original key case, exact primary scalar identity, scalar/primitive-array/scalar-array/Collection cardinality, empty-sequence type evidence, sequence order, i8/i16/i32/i64 spelling, and IEEE bit encodings; non-primary/non-Unicode/null/mixed/nested/type-disagreed/duplicate-key/over-bound cases fail closed with the exact reason or budget and no partial property map.
- HMAC key material and unprotected token payload/header/tag fragments never enter diagnostics or presentation. Public opaque token bytes appear only in their defined request field and are not decoded, normalized, or reflected by failure objects.
- The suite does not classify arbitrary application result bytes as credentials and therefore cannot make a compromised-agent containment claim.
- Redaction behavior is identical in success, failure, retry, cancellation, and restart paths.
- Inventory fixtures pin every transform and threshold byte-for-byte, prove full-value and exact-boundary detection for each transform, prove 15 raw bytes and transforms outside `SECRET_SCAN_TRANSFORMS_V1` are outside the stated claim, and fail before injection on any sentinel/baseline/redaction-marker collision.

- **Done when:** `cargo test -p slingshot-development --test credential_exposure_threats` verifies intended credential delivery, exact temporary-source/long-lived-secret wrapper separation, source-reference-free inclusive diagnostics, metatype-first zero-read redaction and hostile-carrier closed handling, and reports zero collision-checked `SECRET_SCAN_TRANSFORMS_V1` matches at the exact 16-raw-byte threshold across every named unintended channel for both authentication modes and continuation key material, and `scripts/quality` succeeds.
