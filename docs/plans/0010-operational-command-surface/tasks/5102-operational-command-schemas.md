# Command Schemas

A registry row carries two schema digests, and a digest of a schema nobody wrote is a digest of nothing. This task writes both role schemas for every new command, commits their bytes, and keeps the honesty Plan 0003 insisted on: a schema checks the decoded shape and never claims to check the byte contract beside it.

**Steps:**

1. Add the fifty-two new wire names to `COMMAND_WIRE_NAMES` in the ascending order the catalog returns them.
2. Split the per-command bodies into four family leaves and keep the dispatch, the shared helpers, the identifier rule, and the file-name rule in `schema.rs`, so a reader looking for what a command's arguments are finds it beside that family.
3. Write both role schemas for every new command using the shared helpers wherever a shape already exists - the result window, the property value, the property predicate collection, the discovery page - and add helpers for the shapes this plan introduces: the operational listing page, the closed state enumerations, the inline binary payload, the element value set, and the mapping entry.
4. Read every bound from the limits contract by name. No schema keyword restates a number.
5. Commit both schema documents per command under the existing file-name rule, and regenerate the schema manifest and the digest vectors from the code rather than editing them.
6. Keep every schema honest about what it cannot express: serialized member order, raw spelling, minimal integer tokens, and set-like array order stay the byte contract's, and no schema result is offered as proof of them.
7. Give the byte contract the array inventory the new commands need. Each new listing is ordered by a member the contract has no comparator for - a persistent identifier, a symbolic name and version together, an agent, a queue - so each gets a comparator that names the member it orders by, rather than one general comparator that would say less than the rows it governs.

**Tests:**

- Every published command has both role schemas, and every committed schema file equals the one the code builds, byte for byte.
- Sixty-four commands appear in the inventory, in ascending order, matching the catalog exactly.
- Every schema declares the dialect, carries the identifier its role and version determine, and carries the canonical byte contract's digest as its annotation.
- Every accepted argument fixture in every command's fixture file validates against that command's argument schema, and every refused one fails it or is documented as a refusal only the typed constructor can make.
- Every result fixture validates against its result schema.
- Each command's two digests differ, no two commands share a digest, and the manifest's digests equal the ones the catalog publishes.
- Every array a new command carries has an inventory entry, every comparator that inventory names is declared in the module as well as the file, and the contract's own bytes stay canonical.
- The fingerprint vectors cover all sixty-four commands.

- **Done when:** `cargo test -p slingshot-domain --test command_schemas` and `--test command_fingerprint` pass with sixty-four commands, committed bytes equal to generated bytes, every fixture validated against its own schema, and no bound written down a second time.
