# Plan 0005 — Author-Agent Job Transport

> Submit one durable operation to the author-hosted Slingshot agent, follow its Sling Job through interruptions, and publish a verified bounded result.

## Why this plan

The daemon crosses two independent failure boundaries when it runs a command: a local durable operation crosses an authenticated network request, and an accepted Sling Job reports progress over a connection that can disappear at any time. A successful request followed by a daemon crash is ambiguous unless the author treats the stable target-and-generation-partitioned AgentOperationIdentifier derived from the local operation as an idempotency key. Including the never-reused AgentEventStoreGeneration makes later generations derive disjoint identifiers while recovery refuses to re-identify or resubmit old ambiguous work. A disconnected event stream is incomplete unless the author exposes a current job snapshot or replayable history.

This plan makes those recovery properties part of the language-neutral agent contract. The Java implementation remains outside this repository. Slingshot owns Rust protocol types, committed schemas and fixtures, a configurable fake author, and client behavior that is proven against failure injection.

Adobe documents that authenticated author POST requests require a short-lived token fetched immediately before submission and sent as `CSRF-Token` in [AEM as a Cloud Service CSRF protection](https://experienceleague.adobe.com/en/docs/experience-manager-learn/cloud-service/developing/advanced/csrf-protection). Adobe's [AEM 6.5 LTS security checklist](https://experienceleague.adobe.com/en/docs/experience-manager-65-lts/content/security/security-checklist) also describes the cross-site request-forgery framework and recommends a current-host referrer for command-line clients. The transport applies both prerequisites from the selected author identity without accepting caller-supplied header values.

Every remote request goes directly to the configured author endpoint through one ambient-proxy-disabled client. The daemon never dials a publisher endpoint or environment-selected proxy. Replication and publisher-affecting work execute inside the author-hosted Sling Job.

- **0022 — Job State, Storage, and Recovery.** Reduce remote observations through monotonic job and subscription folds, persist bounded target/revision/transport/canonical-contract-partitioned logical-operation/outbox/retry/physical-attempt/shared-ledger facts, anchor every advertised relative-retention duration at daemon request-start, reconcile authenticated high-water resets, coalesce incidents, preserve one logical effect across physical retries and daemon/agent/Adobe Experience Manager restarts, preserve complete extended maintenance bytes/digest across inline and Plan-0004-owned operation-free target-qualified result associations through metadata/read, apply ownership transfer, replay, restart, supersession, and retirement, and run or explicitly resume same-identifier recovery.

## Out of scope

- Java servlet registration, Sling Job consumer code, AEM repository access, and actual command execution.
- Direct publisher connections.
- Browser EventSource behavior.
- Remote job cancellation.
- Credential parsing or token-generation algorithms already owned by Plan 0002.
- Command semantics already owned by Plan 0003.
- Local daemon framing and persistence primitives already owned by Plan 0004.

## Plan dependencies

Plan 0002 supplies validated target configuration, complete opaque `AuthorTargetIdentity`/`SelectedEnvironmentRevision` values, and credential providers with conservative usable-token leases. Plan 0003 supplies the closed command catalog and schemas. Plan 0004 supplies target-scoped daemon operations, durable operation records, and the artifact store. Plans 0006 through 0008 consume the terminal operation behavior proved here.
