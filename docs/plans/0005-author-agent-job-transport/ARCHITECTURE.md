# Plan 0005 — Author-Agent Job Transport

## Architectural boundary

slingshot-domain owns durable remote-job state and identity vocabulary. slingshot-agent-protocol owns closed serializable wire documents plus validated conversions to and from those domain values; it does not define a second state machine. slingshot-agent-connection owns network behavior and depends inward on protocol, domain, and configuration. slingshot-daemon coordinates live recovery with storage. slingshot-test-support owns the fake author.

The author origin is the only permitted remote origin. Publisher addresses may exist in validated profile data but never enter connection selection. One shared authenticated author-client constructor consumes Plan 0002's immutable typed `SelectedEnvironmentSnapshot`; it accepts only the snapshot's author-only target and provider, TLS 1.2/1.3 policy, exact immutable effective platform-plus-selected-additional-author-certificate-authority root bytes with `VerifiedAuthorTrustPolicyIdentity`, direct/no-ambient-proxy policy, and typed insecure-cleartext decision/warning. The Cloud provider's Identity Management Services client separately consumes only the same snapshot's immutable provider-policy-verified platform server-authentication root bytes with `VerifiedIdentityManagementTrustPolicyIdentity`. Neither client dynamically reloads a root source, Plan 0005 cannot substitute or DER-only widen either policy, and selected additional author authorities never authenticate Identity Management Services. The constructor neither reconstructs Plan 0002 identity/transport preimages nor reads profile, credential, certificate, proxy, or trust inputs again. Cloud and every TLS target require ordinary hostname/certificate validation under TLS 1.2 or 1.3. Cleartext is permitted only when the snapshot's typed author target/provider already authorizes Plan 0002's exact loopback case or explicit warned Adobe Experience Manager 6.5 opt-in; a missing/mismatched warning refuses construction. The constructor disables ambient proxy discovery, redirects, automatic decompression, protocol upgrade, `Alt-Svc` migration, and every protocol other than HTTP/1.1 or HTTP/2 before any request can be built; callers cannot replace those policies. Tests trap all proxy variable spellings, publisher/alternate-origin listeners, untrusted roots, TLS 1.0/1.1, hostname mismatch, cleartext without exact typed authority, a forged warning, cross-use of either root set, hostile Identity-Management-Services interception signed only by an additional author certificate authority, and any live root-source reload. The same constructor installs the exact response-header bounds from the typed `AuthorAgentTransportContract` below for every success and error response, including finite documents, event-stream attachment, and artifacts. The HTTP/1.1 parser and HTTP/2 compressed-block/decoded-header-list decoder enforce those limits incrementally before collection: the single-field bound covers one decoded field name plus value, the count bound counts fields, and the aggregate bound applies independently to the raw HTTP/1.1 head, encoded HTTP/2 block, and checked decoded status/field/separator charges. A response is rejected as soon as the next input or decoded field crosses a limit, before an unbounded header collection or route outcome is exposed. Redirects remain disabled for cross-site request-forgery token preflight, capability discovery, command submission, event streams, snapshots, operation/job lookup, and artifacts, including same-origin redirects. Rust declared identifiers spell words in full. Standard wire header names, media types, Adobe product names, and protocol documents retain their externally specified spellings.

## Normative author-agent transport contract

Task `author-agent-transport-contract` first commits canonical `policy/author-agent-transport-contract-1.json` with format literal `slingshot.author-agent-transport-contract/1` and companion `policy/author-agent-transport-contract-1.sha256`. The JSON is UTF-8 without a byte-order mark, contains exactly `format`, `agent_protocol_version`, `limits`, and `formulas`, uses byte-lexicographically ordered ASCII object keys, unsigned minimal base-ten integers, no insignificant whitespace, and one final line feed. The sidecar is exactly the SHA-256 digest of those complete bytes as 64 lowercase hexadecimal bytes plus one line feed. Repository and embedded bytes, the typed read-only `AuthorAgentTransportContract`, all generated schemas, FakeAuthor, storage settings, every fixture/test, capabilities, request/response/event/snapshot documents, and independently implemented agent conformance must agree. Missing, additional, reordered, differently valued, locally redeclared, or fallback public values refuse construction/readiness. The contract has no deployment override; changing a value requires a new protocol/manifest version.

Plan 0005 extends predecessor-owned crate roots through dependency-ordered feature tasks rather than leaving new source files undeclared. Tasks `author-agent-transport-contract`, `agent-identity-and-wire-schema-contract`, and `agent-store-and-logical-execution-contract` serialize their domain-root declarations. `agent-job-storage` declares its new storage repository leaf; `job-snapshot-reconciliation`, `durable-idempotent-submission`, `recovery-and-event-supervisor`, `bounded-structured-results`, and `artifact-download` serialize every new storage or daemon operation-family declaration. Existing Plan 0001–0004 leaves are adopted unchanged unless the task explicitly extends their behavior. Each focused integration test compiles through the public crate tree, so a missing, duplicate, unordered, or orphan module declaration fails the owning task rather than waiting for final executor composition.

## Durable identities and routes

Plan 0004 supplies one persisted RuntimeNamespace, immutable AuthorTargetIdentity, exact SelectedEnvironmentRevision, caller-created local OperationIdentifier, and immutable InstallationIdentifier snapshot committed with local operation admission before executor invocation or network activity. That admission exists only after Plan 0002 has completed its exact `S1 -> listed source/digest verification -> discovered/transitive source-set equality -> S2` generation proof; an incomplete or mismatched generation yields no snapshot and no Plan-0005 admission. Plan 0005 treats Plan 0002's complete typed AuthorTargetIdentity, its SHA-256 output `AuthorTargetIdentityDigest`, SelectedEnvironmentRevision, transport policy, and authentication provider as authoritative opaque values. It uses the target hash directly and never hashes its lowercase rendering. The raw profile-authentication-contract digest is already bound in the opaque target and revision, and the distinct `VerifiedIdentityManagementTrustPolicyIdentity` and `VerifiedAuthorTrustPolicyIdentity` are already bound in the revision. Genuine same-principal secret rotation preserves the supplied target/revision; a canonical metascope or either named trust-policy identity change changes the supplied revision; profile-contract or principal change arrives as changed opaque target/revision values. Plan 0005 never enumerates, reconstructs, or aliases those preimage fields. Capability discovery may then supply the current AgentEventStoreGeneration without creating remote-operation facts or causing a submission effect. This plan reads those operation-owned snapshots and, after the validated capability response but before any POST byte, atomically creates the generation-scoped remote child containing every Plan-0005 derivation preimage and derived identity. Daemon restart, bundle restart, and Adobe Experience Manager restart preserve the admitted snapshots. Any nonterminal target or selected-revision mismatch fails Plan 0004's startup audit byte-preservingly before provider construction or network access; terminal prior-revision history remains read-only. Credential refresh is never used to excuse contract/metascope/trust-policy revision drift.

Two domain-separated, versioned, length-prefixed UTF-8 encodings produce remote identities with committed language-neutral derivation vectors. Each encoding contains its exact role tag and ordered field names/lengths, is hashed with SHA-256, and renders as the role literal `daemon_subscription_` or `agent_operation_` followed by exactly 64 lowercase hexadecimal digits; parsing rejects every other spelling:

- DaemonSubscriptionIdentifier derives from InstallationIdentifier, RuntimeNamespace, and the exact direct AuthorTargetIdentityDigest. It is stable for one opaque target partition's filtered stream and changes whenever Plan 0002 supplies another target; no downstream principal field is a wire preimage.
- AgentOperationIdentifier derives from the same three inputs plus the current AgentEventStoreGeneration and local OperationIdentifier. It is stable for one remote operation only inside that exact author-target/generation partition; the same local operation inputs under a later never-reused generation derive a different wire identifier.

The local OperationIdentifier remains target-scoped user experience identity and never substitutes for either remote identifier. `SelectedCommandContractIdentity` remains exactly the closed ordered five-field tuple of Plan 0003 command wire name, exact semantic contract version, exact SHA-256 digest of canonical `slingshot.command-contract-limits/1`, argument-schema digest, and result-schema digest. `CommandCanonicalJsonContractDigest` is separate provenance: it is the exact SHA-256 digest of the complete canonical `schemas/command-canonical-json-1.json` artifact with format `slingshot.command-canonical-json/1`, not a sixth identity field. Before accepting either role digest, both selected argument and result schema roots must carry annotation `x-slingshot-canonical-json-contract-sha256` exactly equal to that digest; because the annotations are inside the canonical role bytes, both role digests authenticate the same separately executed byte contract. The limits digest is the exact 64-lowercase-hexadecimal value carried by the selected Plan 0003 catalog descriptor; this plan never copies either manifest or defines another limits/canonical value. Storage persists the exact opaque AuthorTargetIdentityDigest but no downstream target-preimage field, exact SelectedEnvironmentRevision, AgentEventStoreGeneration, derivation format, both derived identities, AuthorAgentTransportContractDigest, CommandCanonicalJsonContractDigest, complete five-field SelectedCommandContractIdentity, and SubmittedCommandDigest. The daemon recomputes every value from the exact artifact, both annotated schema roots, persisted Plan-0005 derivation preimages, and the admitted validated Command before any submission or recovery request. Replay, lookup, events, snapshots, results, failures, and artifacts never cross target/revision/generation/transport/canonical-contract/selected-contract/command-digest partitions. Any mismatch on reopen fails closed before provider or network access.

AgentEventStoreGeneration is a persisted nonzero unsigned 64-bit generation number serialized as its canonical decimal string. A new store starts at `1`. Rotation uses checked increment in the same atomic transaction as prior-state movement; when the current value is the unsigned 64-bit maximum, rotation refuses with exact closed `agent_event_store_generation_exhausted` and leaves every byte unchanged. Restart reopens the persisted value. No path wraps, reseeds, randomly replaces, or reuses a generation, including after all prior-generation records retire.
