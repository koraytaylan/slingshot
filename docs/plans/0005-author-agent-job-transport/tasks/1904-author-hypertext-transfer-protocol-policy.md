# Author Hypertext Transfer Protocol Policy

Every author route needs one bounded response head, status, throttling, and deadline interpretation so no client path hangs indefinitely, allocates an unbounded head, or invents different retry certainty.

**Steps:**

1. Commit route/status fixtures for every architecture mapping including token preflight, authenticated high-water capture, stream attachment/reset, three-hundred refusal, 401/403/404, 408/429/500/502/503/504, every other status, valid and bare/malformed/mismatched artifact 404/410 documents, `Retry-After` delta/date/missing/malformed/over-cap, JSON/SSE/artifact Content-Type parameter/duplicate/conflict cases, identity/duplicate/gzip/Brotli Content-Encoding, HTTP/1.1 and HTTP/2 success equivalence, every other protocol, upgrade and `Alt-Svc` migration attempts, bounded 100/101/103 followed by otherwise valid final heads, repeated informational heads, zero/one/multiple final heads, `Trailer` declaration, absent/explicitly-empty/nonempty actual trailers, repeated/conflicting `Content-Length`, `Transfer-Encoding` plus `Content-Length`, invalid transfer-coding chains, HTTP/2 connection-specific/pseudo-header order/duplication violations, trailing bytes, and exact/next `MAXIMUM_AUTHOR_RESPONSE_HEADER_BYTES`, `MAXIMUM_AUTHOR_RESPONSE_HEADER_COUNT`, and `MAXIMUM_AUTHOR_RESPONSE_HEAD_BYTES` boundaries for HTTP/1.1 raw/decoded heads and HTTP/2 encoded blocks/decoded lists on finite JSON, stream, artifact, and error responses; Plan 0002 selected-snapshot author-only target, TLS 1.2/1.3, `VerifiedAuthorTrustPolicyIdentity` with exact immutable effective platform-plus-selected-additional-author-certificate-authority roots, distinct `VerifiedIdentityManagementTrustPolicyIdentity` with immutable provider-policy-verified platform roots, direct/no-proxy, loopback/opted-in/warned cleartext, live root-source edits without reload, explicit-restart either named identity drift, and untrusted-root/cross-use/hostile-additional-author-CA-IMS-interception/TLS-1.0/1.1/hostname/forged-warning/publisher/proxy canaries; and distinct DNS, TCP-connected, TLS-handshake, request-body, header, body-idle, and transfer deadlines before implementation.
2. Implement the one shared authenticated author-client constructor solely from Plan 0002's immutable typed selected snapshot and author provider. Consume its exact author-only target, TLS 1.2/1.3/effective platform-plus-selected-additional-author-certificate-authority root configuration, direct/no-ambient-proxy policy, and typed cleartext authorization/warning without reopening inputs or rebuilding identity/transport preimages. Require the provider's Identity Management Services client to retain the distinct provider-policy-verified platform server-authentication roots from that same snapshot. Forbid dynamic reload, merging, DER-only widening, or cross-use of either root policy. Reject a publisher/alternate origin, untrusted/hostname-invalid TLS, unsupported TLS version, proxy path, or cleartext target lacking the exact upstream authorization/warning. Negotiate only HTTP/1.1 or HTTP/2 and disable redirects, automatic decompression, upgrade, `Alt-Svc`, and protocol migration. Configure the HTTP/1.1 parser and HTTP/2 decoder before collection: reject the next decoded field whose name-plus-value or field count crosses its named limit, and independently reject the next encoded HTTP/2 block byte or checked decoded status/field/separator charge that crosses `MAXIMUM_AUTHOR_RESPONSE_HEAD_BYTES`, for every success/error route. Incrementally charge and reject the first informational head; require exactly one final head; reject `Trailer` declaration; and require the adapter to expose actual trailer-section presence including empty. Reject ambiguous HTTP/1.1 framing, invalid HTTP/2 header semantics, over-bound encoded/decoded heads, and bytes beyond the declared message boundary before exposing a route outcome or finite body. Then implement one closed HypertextTransferProtocolOutcome mapper using named status constants and route kind; expose exact success, Missing, Retired, validated artifact Missing/RetentionExpired, reset, validated nonexecution rejection, conflict, authentication, retryable, and nonretryable request outcomes without response-body text as a code.
3. Parse only bounded canonical `Retry-After` delta-seconds or IMF-fixdate, convert at response receipt with injected wall/monotonic clocks, combine with full jitter, clamp to the named local category cap, and persist the selected relative delay/diagnostic UTC eligibility through the caller's retry transaction.
4. Send `Accept-Encoding: identity`, disable automatic decompression, and after the sole final head passes the shared finite limits require exactly one bounded route-appropriate Content-Type plus absent/identity Content-Encoding. Parse only the pinned optional UTF-8 charset for JSON/SSE and require artifact media type to match the parameter-free manifest value; require artifact 404/410 to carry the closed matching JavaScript Object Notation ArtifactUnavailable document; reject duplicate/conflicting headers/parameters and every other coding before body processing. Accept a finite document or submission outcome only after exact framed end proves no actual trailer section, including empty, and no trailing byte. Reject declared trailers before exposing an event stream or artifact body; reject an actual artifact trailer before publication and treat an undeclared actual event-stream trailer as a reconnecting protocol failure without retracting already committed valid events.
5. Apply `AUTHOR_CONNECT_TIMEOUT_MILLISECONDS` from before DNS resolution through TCP connection; start `AUTHOR_TLS_TIMEOUT_MILLISECONDS` only after TCP connect and end it after authenticated TLS completion; then apply request-body and response-header timeouts as distinct phases. Plain HTTP has no TLS phase and cannot borrow its budget. Apply named total-body/inter-byte idle timeouts to finite documents and named total-transfer/inter-byte idle timeouts to artifacts. Keep established Server-Sent Event liveness heartbeat-driven without a total-body timeout.
6. Preserve SubmissionUnknown after any POST byte for every unvalidated status, header, body, identity, version, or bound outcome—not only retryable statuses/timeouts—and direct the operation to same-identifier lookup-first reconciliation. Expose ConfirmedNotExecuted only when the injected transport proves zero request bytes reached author or a validated identity/generation-bearing rejection proves nonexecution.

**Tests:**

- Every route/status pair maps to exactly one closed outcome, high-water generation mismatch cannot be mistaken for a captured boundary, and redirects receive no follow-up request.
- Every success and error route admits exact HTTP/1.1 and HTTP/2 single-header/count/aggregate encoded-and-decoded response-head maxima and rejects the next input byte/decoded field before route-specific body handling; a head timeout remains distinguishable from each size/count/compression refusal.
- Every proxy spelling and reachable proxy/publisher/alternate-origin canary receives zero connections for token, capability, submission, event, high-water, lookup, snapshot, result, and artifact requests. Plan 0002's distinct selected-snapshot root policies accept only their intended Identity Management Services or TLS 1.2/1.3 author peer; a hostile Identity Management Services endpoint signed only by an additional author certificate authority receives no request. A live operating-system or additional-author-authority edit changes neither client, and untrusted/different/cross-used roots, dynamic reload, hostname mismatch, TLS 1.0/1.1, unauthorized cleartext, or forged/missing warning fail before request bytes.
- Valid delta/date retry values combine with deterministic jitter and never exceed the local named cap; malformed, overlong, past, forward-jump, and backward-jump values cannot bypass it.
- DNS/TCP connect, TLS handshake, request body, response header, artifact idle/total, and finite-body idle/total deadlines each fire at their exact virtual boundary, report their own phase, and free the request task without resetting or borrowing another phase; stream heartbeat liveness remains distinct.
- JSON and reset documents, live streams, and artifacts accept only HTTP/1.1 or HTTP/2 with their exact bounded-head and single media-type/coding shapes; upgrade/migration, first informational head, multiple final heads, trailer declaration, actual empty/nonempty trailers, ambiguous framing, invalid HTTP/2 semantics, duplicate/conflicting headers, unknown parameters, non-UTF-8 charset, gzip, Brotli, transparent client decompression, over-bound encoded/decoded heads, and trailing bytes are rejected at the architecture's pre-body/pre-completion boundary. Artifact 404/410 becomes Missing/RetentionExpired only with its exact status/reason and generation/operation/artifact/slot echo; bare or mismatched errors remain protocol-invalid.
- Submission checkpoints before/after the first request byte cross every valid and invalid status/media/coding/body/version/informational/trailer/framing/identity branch; every post-byte unvalidated branch preserves SubmissionUnknown, performs lookup-first reconciliation, and reuses only the same explicit generation and opaque identifier pair.
- Errors retain bounded status/route/category data without headers, bodies, credentials, or endpoint secrets.
