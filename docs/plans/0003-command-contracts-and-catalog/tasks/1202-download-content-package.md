# Download a Content Package

Represent package creation from roots plus ordered restricted path-selection expressions, returning artifact metadata rather than package bytes.

**Steps:**

1. Commit canonical command/result fixtures and independently authored language-neutral conformance vectors for valid/invalid/boundary PackageName and exact suggested `<package_name>.zip`, root/include/exclusion/structural selection, exact `/content/bar/(.*)/image` matching, matcher bounds, and the full failure/restart/artifact inventory. Include finite selected/structural path sets; selected direct properties versus structural directory-only ancestors; empty selection; overlapping roots; exact filter/XML bytes for literal `(`, `+`, `^`, `$`, backslash, `\E`, ampersand, single/double quote, less/greater-than, supplementary Unicode, and invalid XML scalars; supported/exact-boundary/older/unreadable/capability-mismatched FileVault versions; profile/manifest fields; and every candidate/evaluation/selected/filter/manifest/archive/input/output boundary before implementation.
2. Implement PackagePathSelectionExpression as the exact bounded absolute token grammar: every token is a RepositoryPathSegment, whole-segment `*`, or exact whole-segment `(.*)`. `*` consumes one complete segment and `(.*)` consumes zero or more complete segments in any position. Root has no tokens and matches only root. Reject repeated/trailing slash, `**`, partial asterisks, every other asterisk-bearing token, over-bound bytes/tokens, and checked bound overflow. Preserve accepted bytes; treat every other valid RepositoryPathSegment literally, including regex-looking characters, and invoke no regular-expression API.
3. Implement DownloadContentPackageCommand with a non-empty deduplicated root collection, ordered inclusion expressions, ordered exclusion expressions, and PackageName restricted to a named bound plus ASCII letters/digits/hyphen/underscore; derive exact separately bounded `<package_name>.zip` suggested metadata without using it as artifact identity.
4. State in the serialized schema that roots bound a union of paths/descendants; overlapping roots yield one ascending candidate-path enumeration; every candidate evaluates every inclusion expression in serialized order and then every exclusion expression in serialized order without short-circuiting; an empty inclusion set makes roots include anchors, otherwise every full expression match is an include anchor whose subtree is admitted; every full exclusion match is an exclusion anchor whose entire subtree is removed after inclusion; duplicates collapse; and separately computed structural ancestors connect selected content without selecting siblings/properties/descendants. Roots, include anchors, exclusion anchors, selected content, and structural ancestors each have strict RepositoryPath byte order.
5. Implement the normative nonrecursive/nonbacktracking bottom-up matcher. Allocate only after the checked `(token_count + 1) * (candidate_segment_count + 1)` cell count fits `MAXIMUM_PACKAGE_MATCHER_CELLS`; fill each Boolean cell exactly once in fixed reverse order using the literal, `*`, and `(.*)` recurrence from architecture; charge one `pattern_evaluations` unit before each cell. Rust executes the independently authored pure matcher vectors with exact Boolean result/cell count; those same artifacts are normative input to, but not executed by, the separately built external Java agent's own conformance gate. An agent grammar rejection before enumeration remains stable closed `pattern_rejected` with exact `collection`/`expression_index` and no effect.
6. Generate `slingshot.filevault-filter/1` only from the already finite selected-node and structural-ancestor sets; never translate command expressions or emit command excludes. For each ascending root, order retained paths by depth then UTF-8 bytes, selected wins over structural, emit one fully anchored exact node include, and immediately follow each structural include with the exact direct-property `matchProperties="true"` exclude. Selected nodes serialize through ordinary FileVault `jcr_root`/`.content.xml` export with their direct selected properties; structural ancestors contribute ZIP hierarchy directories only, never `.content.xml`, a property value, sibling, or descendant. Record that a later external import may create a missing directory-only ancestor using FileVault's effective default child node type even though it does not supply replacement properties for an existing ancestor. Empty selection uses the one fixed never-match include and no content entry.
7. Implement the exact language-neutral quoting/XML algorithm from architecture: Java regex `\A\Q...\E\z`, `\E`-literal replacement, fixed structural direct-property suffix, fixed empty expression, single-pass XML 1.0 codepoint/entity handling, and canonical roots/rules/attributes/document bytes. Reject unrepresentable paths as `filevault_filter_unrepresentable`; enforce filter/manifest byte bounds. The output manifest records ordered selected node/property paths, structural directory-only paths, rules, and archive entries so an external package cannot claim broader content.
8. Negotiate `slingshot.filevault-content-package/1` before staging. Support only profile `slingshot.filevault-merge-properties/1` when the installed Apache Jackrabbit FileVault version is at least 3.5.0 and actually exposes `merge_properties` plus `matchProperties`; record exact installed version, profile, mode `merge_properties`, and `acHandling=ignore`. Older, unreadable, or capability-mismatched installations return `filevault_profile_unsupported`; version `1.0.0` has no legacy fallback and makes no claim that legacy merge is equally non-destructive. Slingshot builds/downloads only and never imports.
9. Use checked deterministic `candidate_paths|pattern_evaluations|selected_paths|filter_document_bytes|package_manifest_bytes|archive_entries|uncompressed_input_bytes|package_output_bytes` budgets. Charge every distinct selected content path and structural ancestor before admission, and check the next matcher cell/filter byte/manifest byte/archive entry/input byte/output byte before work. Apply exact closed failures: `root_not_found|root_access_denied` with `root_path`; content-free `filevault_profile_unsupported|filevault_filter_unrepresentable|repository_read_failed|filevault_package_failed|staging_cleanup_failed|artifact_publication_failed|artifact_publication_outcome_unknown`; and `evaluation_budget_exceeded` with its eight-way budget. Pattern/profile/filter/root/read/FileVault/budget/publication-failed cases publish no artifact; cleanup failure leaves only inaccessible agent-private staging; publication outcome unknown preserves indeterminate private publication truth and blocks rebuild pending same-operation reconciliation. Make no hard duration claim for a blocking repository/FileVault call.
10. Pin operation-scoped NotStarted/Staging/PublicationInFlight/Published recovery. Staging is not addressable by the artifact route and is bounded to one private copy. On retry, a verified durable Published mapping/digest returns the same artifact; Staging is removed then rebuilt under the same operation; PublicationInFlight is reconciled before any rebuild; cleanup failure pauses for maintenance and publication ambiguity fails closed. Keep published mapping/bytes through Plan 0005's bounded operation/artifact-retention generation and remove them only after expiry. No branch mutates the content repository or exposes partial bytes.
11. Reuse ArtifactDescriptor in DownloadContentPackageResult under Required `content_package` with exact `application/zip` media type and exact length at or below MAXIMUM_PACKAGE_OUTPUT_BYTES; an inline, absent, additional, over-maximum, differently slotted, or differently typed result is invalid. Request-context validation requires exact `<originating package_name>.zip`, slot/media, and command/result variant before persistence or artifact acceptance.

**Tests:**

- Exact literal segments, whole-segment `*`, and whole-segment `(.*)` serialize byte-for-byte unchanged; `(.*)` is accepted in every position, while `**`, a partial asterisk, and every other asterisk-bearing token are rejected.
- Rust tests prove no regex compilation or matching API is called for PackagePathSelectionExpression; filter-generation vectors independently prove every literal Java-regex metacharacter and embedded `\E` is quoted without widening.
- Empty nonroot, NUL-containing, repeated/trailing-slash, over-byte/token/cell-bound, partial-wildcard, and checked-overflow expressions are rejected structurally.
- Root and filter ordering round-trip exactly; duplicate roots and anchors collapse deterministically before the independently sorted root/include/exclusion/selected/structural sets are produced.
- Independently authored language-neutral matcher fixtures pin exact tokenization, Boolean result, and charged cell count for root, Unicode/literal metacharacters, `*`, `(.*)`, multiple descendant tokens, maximum input, and rejected syntax. The exact `/content/bar/(.*)/image` fixture matches zero, one, and many middle segments and rejects a missing literal prefix/suffix or extra trailing segment. Rust passes the pure matcher inventory here; the external Java project consumes it in its separately owned executable gate.
- Language-neutral vectors pin the five selection sets, then separately pin non-widening selected/structural filter rules, depth/UTF-8 order, selected-over-structural precedence, empty selection, exact regex/XML bytes, XML-invalid rejection, directory-only structural ancestry, selected properties, and every eight-way deterministic budget boundary.
- A committed bounded conformance package manifest requires exact FileVault version/profile/mode/acHandling, `META-INF/vault` metadata/filter and `jcr_root` layout, selected node/property versus structural directory-only inventories, archive entries, and no automatic import. Supported capability probes pass; old/unreadable/mismatched profiles fail without a package or a false legacy-equivalence claim.
- Failure fixtures reject expression text, artifact metadata/package bytes, unknown categories/discriminators, duration-budget literals, false no-publication claims, and surplus fields; the catalog exposes `filevault_profile_unsupported`, `filevault_filter_unrepresentable`, every other exact package failure, and all eight deterministic budget literals for version `1.0.0`.
- Restart vectors distinguish bounded private Staging cleanup/rebuild, verified Published reuse throughout the operation/artifact-retention generation, expiry cleanup, authoritative publication failure, cleanup-maintenance pause, and PublicationInFlight ambiguity that forbids duplicate publication.
- Artifact identifiers, digests, lengths, exact `application/zip` media type, and exact separately bounded `<package_name>.zip` suggested file names enforce independent validation rules and reject inline byte fields; presentation name is not identity and bytes remain opaque without automatic extraction.
