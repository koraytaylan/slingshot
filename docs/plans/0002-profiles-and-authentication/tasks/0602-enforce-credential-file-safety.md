# Enforce Configuration File Safety

Open the required generation manifest and every profile, selection, service-credential, and certificate document through one root-contained authority, then accept only one complete committed source generation.

**Steps:**

1. Build fixtures for the supplied root/account plus `configuration-snapshot.toml`, profile, optional selection, credential, and certificate files with every symbolic-link/reparse/escape/owner/type/permission/access-control/file-identity violation and final-file link count zero, one, and two where the platform can report them. Include a same-owner hard link whose second name is outside the verified root; truncation, growth, same-length modification, evidence change before/during/between/after two reads, first-attempt recovery, exhausted instability, old handle across atomic replacement, exact private source digests, missing/surplus/mismatched source, old/new manifest, mixed generations, publication between S1/sources/S2, and a complete committed replacement.
2. Implement one supported-platform `ConfigurationFilesystemPolicy` that consumes the already-open root-directory handle and exact once-sampled account identity from task `resolve-credential-paths`; it never resamples an effective user/process token or resolves a second home/profile. Apply no-follow/open-reparse-point descendant traversal, a final-file link-count-exactly-one rule, the current-user file boundary with its documented privileged-operating-system-principal caveat, safe directory access, the manifest's exact two-attempt stable-read protocol, and explicit unsupported-platform failure. On Linux require the supplied effective user identifier as owner, bind device/inode/type/link-count/length/modification-time/status-change-time evidence to the same descriptor, reject descriptor link count other than one, query its POSIX access-control list, expand named-user/named-group entries through the mask, reject every effective non-owner file read/write/execute permission and non-owner directory write/create/delete permission, and apply the same prospective mutation rule to directory default access-control lists. On macOS apply the same supplied-identity descriptor-bound owner/mode/device/inode/type/link-count/length/modification-time/status-change-time checks, reject final-file descriptor link count other than one, query extended access-control-list state from that descriptor, and require no extended entries. On Windows require the supplied process-token user Security Identifier as owner; trust exactly it, LocalSystem `S-1-5-18`, and BUILTIN\Administrators `S-1-5-32-544`; require a protected canonical Slingshot-root discretionary access-control list and canonical descendant lists whose inherited entries trace exactly to the verified parent; reject every reparse component and final link count other than one; bind evidence to handle-observed volume serial number, 128-bit file identifier, type, link count, end-of-file length, last-write time, and change time; expand generic masks and inherited entries; and reject a null/absent list or any noncanonical, object/callback/conditional, untraceable, or otherwise unevaluable entry. The three trusted principals may hold data/control rights; every other Security Identifier may hold only `READ_CONTROL`/`SYNCHRONIZE` and no data or mutation right. Evaluate deny entries before allow entries and never use a deny to excuse a forbidden untrusted allow.
3. On one verified final-file handle, capture pre evidence; read bounded A from offset zero to the recorded length/end; capture middle evidence; rewind; read independently bounded B; and capture post evidence. Accept only equal evidence/bytes with valid policy. Otherwise perform at most `MAXIMUM_CONFIGURATION_STABLE_READ_ATTEMPTS = 2` complete root-relative attempts; exhausted instability returns only `configuration_file_changed_during_read`. State truthfully that a handle opened before atomic rename may return the complete old object. Return only a role-unknown `SensitiveConfigurationDocument` plus internal source identity, perform no parsing or later reopen, zeroize mutable owned read buffers on disposal, and explicitly exclude a malicious same-account writer without claiming zeroization of dependency/operating-system buffers.
4. Implement parser-independent `ConfigurationGenerationCoordinator<Inspection>` around that authority. On each of at most `MAXIMUM_CONFIGURATION_GENERATION_ATTEMPTS = 2`, stable-read/parse S1; enumerate profiles boundedly; make one handle-relative no-follow optional-presence observation for exact `selection.toml` and require it to agree with S1; stable-read every sorted listed source under `MAXIMUM_CONFIGURATION_SOURCE_DOCUMENT_BYTES`; privately verify SHA-256; checked-add the stable recorded length and reject before retaining a document that would cross `MAXIMUM_CONFIGURATION_GENERATION_SOURCE_BYTES`; invoke a bounded `ConfigurationSourceInventoryInspector<Inspection>`; require its discovered/transitive role inventory, class-specific byte limits, and S1 inventory to agree exactly; stable-read S2; and require S1=S2. Return `VerifiedConfigurationGeneration<Inspection>` with role-tagged opaque documents only after equality. Exhausted missing/mixed/changed/unlisted/surplus/aggregate-over-limit/digest-mismatched state yields only `configuration_snapshot_inconsistent`. Never expose a source digest. Pin the writer order: synchronize safe temporary sources, atomic-replace and synchronize them, then atomic-replace/synchronize the manifest last.
5. Make deterministic fakes implement both per-file and generation contracts across every supported row with a fake inventory inspector and no profile-loader, credential-domain, JSON, PEM, trust, or key dependency.
6. Select any native observation by the exact Plan 0001 supported-platform row. Run every logical case through deterministic all-row fakes. At most the current matching native row may run its actual policy and must emit an explicitly untrusted row-labelled report; it cannot claim another native row passed. Plan 0009 owns provider-authenticated aggregate native evidence.

**Tests:**

- `credential_filesystem` rejects every symbolic link/reparse point, final-file link count other than one—including a same-owner external hard-link alias—ownership, type, permission, exhausted-instability, unequal-byte/evidence, or incomplete generation; a stable old-or-new file may participate only when its bytes match the one unchanged commit inventory.
- Deterministic Linux cases prove mode bits plus masked named/default POSIX access-control-list effective access and descriptor identity/length/time stability; deterministic macOS cases prove an extended access-control-list entry cannot hide behind safe mode bits.
- Deterministic Windows cases pin the exact owner Security Identifier, protected-root/canonical-descendant inheritance chain, generic-mask expansion, reparse, link-count, volume/file-identifier, length, last-write-time, and change-time boundaries; ordinary LocalSystem and BUILTIN\Administrators access is accepted, while an equivalent untrusted-Security-Identifier allow is rejected.
- Safe snapshot/profile/selection/credential/certificate references return only equal twice-read sensitive documents through one verified handle per attempt; source counts and bytes at 16,777,216 succeed, the next source/byte is refused before retention, same-role reuse deduplicates, every cross-role/fixed-location collision refuses, and old/new rename plus all mixed-generation publication cuts have exact outcomes across two whole-generation attempts.
- Root resolution and descendant verification use the identical injected sampled account identity; a fake that attempts to change effective user/process token between them is rejected without a second account lookup or document read.
- The generic authority/coordinator has no profile parser or credential-domain/JSON/PEM/trust/key dependency, its fake inspector proves the generic seam, and no API returns a path intended for later reopen.
- A native observation identifies and matches only its current exact supported row, is labelled untrusted, and makes no aggregate support claim; the deterministic fake separately covers all abstract rows.

- **Done when:** `cargo test -p slingshot-configuration --test credential_filesystem` proves every supported-row policy, exact per-file and whole-generation retry boundaries, truthful old-or-new rename behavior, one sampled account identity/root-contained handle authority, and refusal of every resampling, link, owner, type, permission, instability, or mixed-generation violation without exposing private comparison digests; native aggregate evidence remains Plan 0009-owned.
